# cadcraft-arch 构件数据存储规格（块属性方案）

- 版本：v1.1（spec-first，仅业务规则；v1.1 依据实测补入实现补遗，见 §9）
- 适用：面向 CADCraft 的自研建筑智能绘图插件（项目名 `cadcraft-arch`）
- 状态：方案 A（块属性自研）已确认并已按本规格实现 v0.1

## 1. 背景与约束

### 1.1 为什么用块属性

CADCraft 0.20.1 实测结果：

| LISP 能力 | 实测结果 |
|---|---|
| `entmake` / `entget` / `entmod` / `entdel` / `entlast` / `entnext` | 可用 |
| `ssget` / `ssadd` / `ssdel` / `ssname` / `sslength` | 可用 |
| `tblsearch` / `tblnext` / `blocks` | 可用 |
| `command` / `vl-cmdf` / `defun c:NAME` / DCL 对话框 | 可用 |
| `regapp` / `entmakex` / `setxdata` / `getxdata` | **不可用**，报 `no function definition` |
| `entmake` 带 `-3`（XData 组） | **返回 nil**，即使 APPID 表中已有 `CADCRAFT_ARCH` / `CADCRAFT` |

即 CADCraft 当前版本不支持 AutoCAD XData。因此本插件的构件数据**不使用 XData**，改用 CADCraft 原生的**块定义 + 内嵌 ATTRIB（属性）**作为自研构件数据载体。该方案不依赖任何天正私有实体，全部数据结构由本项目自行设计。

### 1.2 合规边界

- 本项目只实现建筑绘图领域的通用业务行为（墙体相交、门窗依附、轴网生成、房间搜索），所有数据模型与几何算法自行设计。
- 不读取、分析、复刻、引用天正、TCH、TRX 内部代码、伪代码、内存结构、函数地址或私有二进制存储。
- 几何算法采用公开标准：线段求交、向量几何计算、Sutherland-Hodgman 多边形裁剪。
- 不生成 AutoCAD ARX / BRX / C++ TRX 代码，主逻辑使用 CADCraft LISP。

## 2. 总体数据模型

### 2.1 构件分层

```
图纸（Drawing）
└── 轴网（AxisGrid）          —— 轴网为全局定位基准
    └── 墙（Wall）            —— 由轴网或坐标定位
        └── 门窗（Opening）    —— 依附于某一段墙
    └── 房间（Room）          —— 由闭合墙体围合生成
```

构件之间的关系：

| 关系 | 约束 |
|---|---|
| 轴网 → 墙 | 墙的端点可锚定在轴网交点上（可选，锚定后随轴网更新） |
| 墙 → 门窗 | 门窗必须依附于一段已有墙，门窗宽度不得超过所属墙段长度 |
| 墙 → 墙 | 墙与墙相交时按通用几何规则处理（求交、切断、合并），见 §5 |
| 房间 → 墙 | 房间由闭合的墙环围合，房间边界是墙的几何子集 |

### 2.2 构件标识

每个构件由两部分组成，二者必须一致：

1. **几何实体**：图纸中真实存在的实体（LWPOLYLINE / INSERT 块参照 / LINE 等），拥有 CADCraft 句柄。
2. **数据记录**：写在构件自身块属性上的自研字段集合。

**一致性规则**：构件的语义信息只存在数据记录里；几何实体负责画出来。两者通过**构件类型 + 构件编号**一一对应。禁止在几何实体的图层名、线型名等非数据位置编码语义，避免与绘图规范冲突。

## 3. 构件类型与属性字段

所有构件使用统一前缀的块属性标签，命名规则：`AA_` + 类型缩写 + `_` + 字段名。
`AA_` 表示 cadcraft-arch 命名空间，避免与其它插件的属性标签冲突。

### 3.1 轴网（AXGRID）

块名：`AA_AXGRID`

| 属性标签 | 类型 | 说明 | 必填 |
|---|---|---|---|
| `AA_TYPE` | 字符串 | 固定值 `AXGRID`，构件类型标识 | 是 |
| `AA_ID` | 字符串 | 轴网编号，如 `AX001`，图纸内唯一 | 是 |
| `AA_XCOUNT` | 整数 | X 方向轴线数量 | 是 |
| `AA_YCOUNT` | 整数 | Y 方向轴线数量 | 是 |
| `AA_XSPACE` | 实数 | X 方向轴线间距（图纸单位） | 是 |
| `AA_YSPACE` | 实数 | Y 方向轴线间距（图纸单位） | 是 |
| `AA_XSTART` | 实数 | X 方向首轴坐标 | 是 |
| `AA_YSTART` | 实数 | Y 方向首轴坐标 | 是 |
| `AA_VER` | 字符串 | 轴号（A、B、C…），X 方向自上而下 | 否 |
| `AA_HOR` | 字符串 | 轴号（1、2、3…），Y 方向自左而右 | 否 |

业务规则：

- 轴网生成后，轴线绘制在专用图层（建议 `AA-AXIS`），轴号文字绘制在 `AA-AXISTEXT`。
- 轴网数据是**唯一事实源**：修改间距或数量后，应重新生成几何，而不是只改属性。
- 轴网编号在图纸内唯一；重复编号视为数据错误。

### 3.2 墙（WALL）

块名：`AA_WALL`

| 属性标签 | 类型 | 说明 | 必填 |
|---|---|---|---|
| `AA_TYPE` | 字符串 | 固定值 `WALL` | 是 |
| `AA_ID` | 字符串 | 墙编号，如 `W001`，图纸内唯一 | 是 |
| `AA_THICK` | 实数 | 墙厚（图纸单位），默认 240 | 是 |
| `AA_KIND` | 字符串 | 墙类型：`EXTERNAL`（外墙）/ `INTERNAL`（内墙）/ `PARTITION`（隔墙） | 否，默认 `INTERNAL` |
| `AA_MAT` | 字符串 | 材料标识，如 `CONCRETE` / `MASONRY` / `LIGHT` | 否 |
| `AA_AX1` | 字符串 | 起始轴线编号（可空） | 否 |
| `AA_AX2` | 字符串 | 终止轴线编号（可空） | 否 |
| `AA_LEN` | 实数 | 墙段长度（由几何实测，不手工填写） | 自动 |

业务规则：

- 墙以**中心线**表示，绘制为 LWPOLYLINE；显示时按墙厚向两侧偏移生成双线。**墙厚是属性字段，不是几何的一部分**——改墙厚只改属性并刷新显示，不删除几何。
- 墙段可为直线段或折线段（多段）。折线墙的每一段共享同一 `AA_ID`。
- 墙的端点锚定轴线时，`AA_AX1` / `AA_AX2` 记录轴号；未锚定时留空。
- 墙编号在图纸内唯一。
- 墙厚必须为正实数，否则视为数据错误。

### 3.3 门窗（OPENING）

块名：`AA_OPENING`

| 属性标签 | 类型 | 说明 | 必填 |
|---|---|---|---|
| `AA_TYPE` | 字符串 | 固定值 `OPENING` | 是 |
| `AA_ID` | 字符串 | 门窗编号，如 `D001` / `W001`，图纸内唯一 | 是 |
| `AA_KIND` | 字符串 | `DOOR`（门）/ `WINDOW`（窗）/ `DOORWIN`（门连窗） | 是 |
| `AA_WIDTH` | 实数 | 洞口宽度（图纸单位） | 是 |
| `AA_HEIGHT` | 实数 | 洞口高度（图纸单位），门默认 2100，窗默认 1500 | 是 |
| `AA_SILL` | 实数 | 门槛/窗台高度（图纸单位），默认 0 | 否 |
| `AA_FRAME` | 实数 | 窗框厚（构造尺寸，默认 60，可逐樘给定；不随墙厚等比缩放） | 自动 |
| `AA_NO` | 字符串 | 门窗编号，缺省按尺寸生成（门 `M0921`、窗 `C1215`、门连窗 `MC…`） | 自动 |
| `AA_LABELSIDE` | 字符串 | 编号所在侧：`in`（室内，默认）/ `out`（室外）/ `auto`（沿用旧 -Y 侧） | 自动 |
| `AA_WALLID` | 字符串 | 所属墙的 `AA_ID` | 是 |
| `AA_POS` | 实数 | 洞口中心到所属墙**起始端点**的偏移距离（图纸单位） | 是 |
| `AA_SIDE` | 字符串 | 洞口在墙的哪一侧：`LEFT` / `RIGHT`，相对墙的前进方向 | 否，默认 `CENTER` |

业务规则：

- 门窗必须依附于一个已存在的墙（`AA_WALLID` 必须能在图中找到对应 `WALL`）。找不到时视为数据错误，拒绝写入。
- 洞口宽度必须为正实数，且**不得超过所属墙段的可用长度**（墙段长度减去已有洞口占用）。超出时拒绝写入并报告。
- `AA_POS` 必须落在所属墙段范围内（0 到墙段长度之间）。
- 门窗几何画在专用图层（建议 `AA-OPENING`），门窗符号（门扇弧线、窗四条线）作为块内嵌几何，随块一起插入。
- 同一墙段上的多个洞口按 `AA_POS` 排序，不允许重叠。

### 3.4 房间（ROOM）

块名：`AA_ROOM`

| 属性标签 | 类型 | 说明 | 必填 |
|---|---|---|---|
| `AA_TYPE` | 字符串 | 固定值 `ROOM` | 是 |
| `AA_ID` | 字符串 | 房间编号，如 `R001`，图纸内唯一 | 是 |
| `AA_NAME` | 字符串 | 房间名称，如 `客厅` / `卧室` | 否 |
| `AA_AREA` | 实数 | 房间净面积（由几何实测计算，不手工填写） | 自动 |
| `AA_PERIMETER` | 实数 | 房间周长（由几何实测计算） | 自动 |
| `AA_WALLS` | 字符串 | 围合该房间的墙编号列表，分号分隔，如 `W001;W002;W003` | 是 |
| `AA_PTS` | 字符串 | 房间净空轮廓点串，`"x,y;x,y;..."`，2 位小数；改名/重建的房间几何依据 | 自动 |

业务规则：

- 房间由**闭合的墙环**围合而成。围合的墙必须首尾相接形成闭环。
- 房间面积与周长由几何实测计算（用公开的多边形面积/周长算法），不手工填写。计算结果与属性值不一致时，以几何实测为准。
- 房间边界是墙的几何子集：房间轮廓由围合墙的中心线偏移半墙厚得到。
- 房间编号在图纸内唯一。
- 房间名称可空；无名称时只显示编号。
- 房间名称是块里那句 TEXT（唯一的可见文字），**改属性改不动文字**——名称变更必须走"整体重建"（§9.17）。

业务规则（名称变更，`set_room`）：

- 依据 `AA_PTS` 重建，不重算几何：面积、周长、围合墙环沿用原值，重建后回读必须一致（面积容差 1e-2 mm²）。
- 同名即"无变更"：返回 `changed:0`，不写盘（幂等，文件哈希不变）。
- 未知编号直接拒绝，并回列现有房间清单；图纸字节不变。
- 动图前备份 `.bak`，任何异常整文件回滚；成功后删除备份。
- 缺 `AA_PTS` 的旧图（无轮廓数据）拒绝改名，提示用 `room` / `room --auto` 重建该房间。

业务规则（门窗表，`openings_report`）：

- 同编号（`AA_NO`）合并成一行：类型、洞口宽/高（mm）、樘数、所在墙（分号分隔）。
- 编号缺省由尺寸生成，因此同尺寸的同类门窗自动并成一行、樘数累加；`AA_NO` 被手工改成别的值就单独成行。
- 导出 CSV 同样 UTF-8 带 BOM，末行 `合计,N 种,……,M 樘`。
- 图上表格用 `draw_table`：6 列（编号 1300 / 类型 1100 / 宽 1200 / 高 1200 / 樘数 900 / 所在墙 2200），标题合并居中、表头居中。

业务规则（房间汇总，`rooms_report`）：

- 一张表一行一个房间：编号、名称、净面积(mm²)、净面积(m²)、周长(mm)、围合墙；末行为合计（间数 + 总面积）。
- CSV 编码 UTF-8 带 BOM（只写一份 BOM），保证 Excel 双击不乱码。
- 图上表格用原生 `table` 命令生成，**不用 `eattext` 抽取**（抽取表是固定 10 列英文列名，且默认尺寸小到在图里只是一条短线）。
  表结构：4 列（编号 / 名称 / 净面积(m²) / 周长(mm)），中文标题 + 合计行；`rowHeight=340`、`colWidth=1800`（标量，引擎不接受数组）、`textHeight=180`。
- 插表前必须先建并切换到 `AA-TABLE` 表格样式（`textHeight` / `margin`），否则默认样式字高几乎不可见。
- **分列宽度**：`table` 的 `colWidth` 只收标量，无法一次给不同宽度；实现为"先 1 列建表（编号宽 1000）→ `table.insertcol {width}` 依次加列（名称 2000、面积 1800、周长 1800）→ `table.set` 逐格填字 → `table.merge` 标题跨 4 列 → `table.cellstyle` 套 `Title` / `Header` 使标题与表头居中"。这套组合已实测可行。

## 4. 数据存储结构

### 4.1 块定义结构

**修正（v1.1，实测后确定）**：不使用"每种构件一个共享块定义"，改为**每个构件一个独立块定义**。

原因：块参照的缩放恒为 1（§4.2），而墙长、房间轮廓、轴网范围逐构件不同；共享块定义只能靠非 1 缩放或改写属性来适配，前者违反缩放规则、后者会让几何与属性脱节。独立块定义让"一个构件 = 一个块参照"，移动/复制/删除天然原子化。

块定义命名：`AA_<类型>_<构件编号>`，例如 `AA_WALL_W001`、`AA_OPENING_D001`、`AA_AXGRID_AX001`、`AA_ROOM_R001`。

```
块定义 <AA_类型_编号>
├── 块属性定义（ATTDEF，定义在块记录内，全部 invisible）
│   └── 各 AA_* 字段（见 §3）
└── 块内几何（随插入一起复制）
    ├── 轴网：轴线 LINE / 轴号 TEXT
    ├── 墙：双侧墙线 LINE（**不画中心线**，中心线只作语义线，画出来会横穿门窗洞口）
    ├── 门窗：洞口边线 LINE + 门扇线/弧 ARC 或窗平行线（门扇**从墙面起画**，不穿墙身）
    └── 房间：名称 TEXT（**不画轮廓线**，轮廓与墙面完全重合，会被误读成墙线且横穿门洞）
```

规则：

- **属性一律不可见**（invisible = true）。属性只作数据载体，不在图纸上产生文字噪音；需要看数据时用 `aa_cmd.py show` 回读。
- 属性的默认值由 ATTDEF 给出；插入时通过 `attribs` 覆盖为实际值。
- 块定义与块参照的属性标签集合必须一致；不一致时视为数据错误。
- 块定义名即构件身份的一部分：找不到对应块定义 = 构件不存在。

### 4.2 块参照（INSERT）

- 图纸中每个构件是**一个块参照**（INSERT 实体），属性值写在块参照上。
- 块参照通过 `AA_TYPE` + `AA_ID` 唯一标识；同一 `AA_ID` 不允许出现两个块参照（重复视为数据错误）。
- 块参照的位置由插入点决定，旋转与缩放默认为 1:1、0 度；缩放非 1 的构件视为数据错误（本插件不使用非 1 缩放，避免属性值与几何尺度不一致）。

### 4.3 命名空间与冲突

- 属性标签统一以 `AA_` 前缀开头。
- 块名统一以 `AA_` 开头。
- 图层建议统一以 `AA-` 开头。
- 本插件不写入、不修改任何不属于 `AA_` / `AA-` 命名空间的对象。读取图纸时只认 `AA_` 前缀的属性标签。

## 5. 几何算法规则（公开标准）

以下算法均使用公开标准，自行实现，不对齐任何私有实现流程。

### 5.1 墙体相交

- 墙与墙相交的判定使用**线段求交**：两线段求交点，判定是否在线段参数区间内（公开的向量几何算法）。
- 相交后按规则处理：
  - 交点落在任一段墙的**内部** → 该墙在交点处**切断**，分成两段；两段共享同一逻辑墙号（`AA_ROOT`），首段沿用原 `AA_ID`，其余分段分配新 `AA_ID`。
  - 交点只落在端点（T 形衔接、转角）→ 不切断，视为相接。
  - 容差取图纸单位的千分之一，可配置。
- 切断只改变几何与分段，不改变墙厚、材料、类型等属性；分段通过 `AA_ROOT` 聚合为同一道逻辑墙。
- **合并**：`AA_ROOT` 相同、且能排成共线首尾相接链的多个分段，合并回一整段（撤销切断）；也可显式指定若干堵墙人工并段。合并后沿用链首编号，`AA_ROOT` 归位为自身编号，墙厚不一致视为拒绝条件。详见 §9.11。

实现补遗：切断采用"整网重建"式——先算完全部分段与裁剪后的墙线，再备份、拆旧、重建、回迁门窗，任何一步异常整体回滚（见 §9.8）。

### 5.2 门窗开洞

- 门窗在所属墙的中心线上按 `AA_POS` 定位，洞口宽度沿墙方向展开。
- 开洞几何：在墙中心线上截取洞口区间 `[AA_POS-宽/2, AA_POS+宽/2]`，向两侧按半墙厚偏移，得到洞口轮廓。
- 墙与洞的关系是**真实开洞**：洞口区间内墙身两侧线断开，洞口端部保留垂直于墙的边线（门垛/窗垛）。墙的中心线**不落图**（v0.3.2 起删除），只作语义线用于量距/面积。
- 门符号：合页落在**墙面**上（局部 +Y 侧），门扇线从合页沿墙法向画出（长度 = 洞宽），开启弧以合页为圆心、半径 = 洞宽，从门扇扫到另一侧墙面。门扇线不得从墙轴线起画——那会穿过墙身，图面看起来像墙体没断。
- 窗符号：按 GB/T 50104 门窗图例的"**四条平行细实线**"画——贴墙面两条（±t/2，窗框外沿）＋ 内侧两条（墙面内退**窗框厚**，即 ±(t/2-frame)），两端各一道洞口边线（垛线）。窗框厚默认 60：240 墙即 ±120/±60，370 墙为 ±185/±125；可逐樘给定（如 40 => ±80）。窗框厚是构造尺寸，不随墙厚等比缩放（旧版按 ±t/4 等比缩放，370 墙会画成 ±92.5，与 60 框厚不符）。只有两条线不构成窗图例，会被读成"墙里夹了根线"。
- 门窗编号：类型 + 洞口宽高各两位分米（门 `M0921`、窗 `C1215`、门连窗 `MC…`），`AA_NO` 可覆盖。编号文字落在洞口**外侧**（墙面外 250，避免压住窗的四线/门扇线），沿墙居中、字高 180；墙块插入角为 180° 时给文字补 180° 旋转（并同步翻转插入点），否则编号在图上是倒字。
- 洞口与墙仍是两个独立构件（各自的块参照与属性）：墙块内只负责"洞口的缺口"，门窗块内负责符号（门扇+开启弧、四线窗）与尺寸属性。改动洞口即触发所属墙块重建，无需双写几何。
- 同一墙段上的多个洞口按区间并集计算缺口；洞口之间、洞口到墙端必须留出实墙段（重叠校验不通过即拒绝写入）。

### 5.3 轴网生成

- 轴线为点划线（线型 `CENTER`），出图时穿过门洞也不会被误认为墙线。
- 轴号按 GB/T 50104 画细实线圆圈：直径 8mm（1:100 出图 => 800 图元单位），**圆与轴线端相切**，编号写在圈内居中，字高 3mm（=> 300）。
- 图档新建时只有 `Continuous`，生成轴网前必须 `linetype {"load":"*"}` 载入内置线型库。
- 轴号文字与圆圈落在轴号层（默认 `AA-AXISTEXT`），轴线落在轴线层（默认 `AA-AXIS`），两层分离。

- 轴网按 `AA_XCOUNT` / `AA_XSPACE` / `AA_XSTART` 等参数生成等距轴线，使用**等差数列**（公开算术规则）。
- 轴号按顺序编号，X 方向用字母序（A、B、C…），Y 方向用数字序（1、2、3…）。
- **线型**：轴线使用细点划线（`CENTER`），轴号文字保持默认线型。图档新建时只带 `Continuous`，因此生成轴网前必须先载入内置线型库（`linetype` 的 `load` 传 `*`），再对线实体逐句柄设线型；字号/文字高度与层名一样走配置。
- 轴线整根贯穿，**不在门窗洞口处断开**（与制图习惯一致；靠点划线线型与墙体实线区分）。

### 5.4 房间搜索

- 房间由闭合墙环围合。两种入口：
  - **显式给环**：用户/AI 按环形顺序给出墙编号，校验墙存在、相邻首尾相接、末墙回到首墙起点。
  - **自动搜环**：不给墙环，由程序枚举图面上所有闭合房间。
- 自动搜索算法（平面图**半边面遍历**，公开标准，线性复杂度）：
  - 顶点 = 墙端点与打断点（按 0.001 mm 网格吸附），边 = 墙中线（子段）；
  - 每条半边只属于一条面的边界；沿"顶点处取逆时针紧前一条出边"走一圈即一个面；
  - 有界面（逆时针、面积为正）即房间；外轮廓（顺时针）与面积为零的退化面（开放缺口、悬挂墙）丢弃；
  - 连续的同墙子段在成环时并回一个墙号，写入 `AA_WALLS`。
- **打断只用于搜索，不改图纸**：隔墙端点落在长墙中段（T 接）、或两墙非共线相交（十字交叉）时，仅在搜索阶段切开长墙；因此不需要先执行 `split`，图纸几何与属性都不受影响。
- 房间边界允许落在某堵墙的中段；净面积按每条边界边的实际半墙厚向内偏移、相邻偏移线求交后计算。
- 自动编号按 `前缀 + 三位序号`（如 `R001`）分配，跳过已占用编号；`AA_NAME` 缺省取编号。
- 幂等：以"围合墙编号集合"判重，同一墙环已有房间则跳过，重复执行不产生重复房间。
- 面积与周长一律由几何实测计算（多边形面积/周长，公开标准），不手工填写。
- 未闭合的墙段不参与房间搜索；房间内不接墙的悬挂墙不构成房间边界。

## 6. 校验与验收规则

所有写入操作必须通过校验，**校验不通过则拒绝写入，并报告具体原因**。禁止"先写入再补救"。

### 6.1 通用校验

| 校验项 | 规则 |
|---|---|
| 构件类型 | `AA_TYPE` 必须是 §3 中定义的四种之一 |
| 构件编号唯一 | `AA_ID` 在图纸内不得重复 |
| 命名空间 | 属性标签必须以 `AA_` 开头 |
| 缩放 | 块参照缩放必须为 1 |
| 数值范围 | 所有长度、面积、厚度必须为正实数（面积、周长为非负） |

### 6.2 类型专属校验

- **轴网**：`AA_XCOUNT`、`AA_YCOUNT` 必须 ≥ 1；间距必须 > 0。
- **墙**：墙段长度必须 > 0；`AA_THICK` 必须 > 0。
- **门窗**：`AA_WALLID` 必须存在；`AA_WIDTH` 必须 > 0 且不超过所属墙段可用长度；`AA_POS` 必须落在墙段范围内；同墙段洞口不得重叠。
- **房间**：围合墙必须形成闭合回路；面积与周长必须与几何实测一致。

### 6.3 验收方式

每个功能完成后，用**回读校验**验收，而不是只看命令返回：

1. **写入后回读**：保存图纸，重新打开，读取构件的属性与几何。
2. **属性核对**：回读到的属性值与写入值一致。
3. **几何核对**：回读到的几何与预期一致（如墙段长度、门窗洞口位置、房间面积）。
4. **一致性核对**：构件类型、编号、所属关系在回读后仍然正确。
5. **不谎报**：任何一步校验失败，都报告失败原因，不报告成功。

## 9. 实现补遗（实测平台约束，v1.1）

本节记录 CADCraft 0.20.1 实测中与文档不符或未文档化的行为。这些不是设计选择，而是平台约束；后续版本若上游修复，可相应简化。

### 9.1 写入管线

一次构件写入固定为五步（每步之间必须落盘，cadcraft-cli 是独立进程）：

1. **LISP 生成几何**：`entmake` 建 LINE / LWPOLYLINE / TEXT / ARC，返回尺寸元数据（不返回句柄）。
2. **原生 `attdef`** 定义该构件的全部属性（invisible）。
3. **原生 `block`** 以"几何句柄 + 属性句柄"归集为块定义（`keep: delete`，源实体消失）。
4. **原生 `insert`** 带 `attribs` 插入块参照，得到唯一一套带值的属性。
5. **回读校验**：`entities` 读回属性与定位，逐项比对，不一致即失败。

关键原因：LISP 的 `entmake` 对 `ATTRIB` / `SEQEND` 返回 nil，**纯 LISP 无法给块参照挂属性**；只有原生 `insert` 的 `attribs` 参数能写出属性。

### 9.2 读取边界

- LISP **读不到属性**：`(ssget "X" '((0 . "ATTRIB")))` 返回 nil；从 INSERT 走 `entnext` 也拿不到属性子实体。
- 属性回读只能走原生 `entities`（单件，含 `geometry.attribs[].text.value`）或 `eattext`（批量导 CSV）。
- 因此"校验"逻辑放在驱动层（Python），LISP 只负责几何与数学。

### 9.3 `entlast` 不可用

同一段 LISP 内连续 `entmake` 多个实体，`entlast` 始终返回同一个实体（实测 3 个实体全报句柄 100，而实际句柄是 100/101/102）。
替代方案：操作前后各取一次 `entities` 句柄集合，做差集得到本次新建句柄，按句柄数值排序还原创建顺序。

### 9.4 旋转语义不一致

`insert` 的 `rotation` 入参按**度**处理，`entities` 回读的 `geometry.rotation` 是**弧度**。驱动层统一规则：写入用度、回读按弧度换算，两者不混用。

### 9.5 属性文本位置

属性由 ATTDEF 的插入点决定，随块参照一起旋转平移。因为属性全部 invisible，位置不影响显示；不要依赖属性文字位置做任何业务判断。

### 9.6 房间搜索的落地方式

§5.4 描述的"自动搜索闭合回路"在 v0.1 中改为**显式墙环 + 强校验**：由上层按环形顺序给出墙编号，驱动层校验首尾相接与闭合、再做内偏移求面积。这样每一步都可解释、可回读、失败原因明确。

v0.4 补回了自动搜环，并改用"半边面遍历"而非枚举回路（回路数指数级，平面图的面是线性的）。落地时踩到三个坑，均已修正：

1. **遍历循环少记最后一条边**：若"回到起点就 break"，收尾的那条半边没被 append，四墙闭环只搜出 3 堵墙。改为每步先进 `face_edges` 再判闭合。
2. **T 接不成顶点**：隔墙端点落在长墙中段时，图不是平面图，只能搜出 1 间。改为搜索前按"其它墙端点落在本墙内部 / 两墙非共线内部相交"切子段，成环后再把连续同墙子段并回一个墙号。**切分只存在于搜索过程，不改图纸**，因此不需要先跑 `split`。
3. **房间边界落在墙中段**：`create_room` 原来只接受"整堵墙首尾链"。重构为 `_room_inner`（有序边界边 → 净轮廓 + 面积）、`_store_room`（落图 + 属性 + 回读）、`create_room`（显式墙环入口）、`create_room_edges`（自动搜环入口），两条路径共用同一套面积与落图逻辑，避免两份实现漂移。

### 9.7 验收口径

每个功能配一份测试（`tests/test_*.py`），检查项固定为四类：

1. 块参照存在、块定义名正确；
2. 属性逐项等于输入值；
3. 几何量（墙长、角度、洞口数、房间净面积）与解析值一致；
4. 非法输入被拒绝，且**图纸上不留下半成品实体**（比对拒绝前后的参照数量）。

`tests/run_all.py` 顺序跑全部测试，任一失败即非零退出。

### 9.8 墙线裁剪（v0.2）

墙块的块内几何只有两侧墙线（v0.3.2 起不再画中心线）。若两侧线按墙长画满，转角与交叉处会出现"墙线穿进另一堵墙"的脏线（实测确认）。处理办法：

1. **驱动层算裁剪**：把本墙的一条侧线（在墙局部坐标系里是 y=±t/2 的一条线段）变换到每一堵邻墙的局部坐标系，用 Liang-Barsky 在矩形 `[0, L邻] × [-t邻/2, +t邻/2]` 内求交，得到被邻墙覆盖的参数区间；从 [0,1] 中挖掉这些区间，剩下的子段即为要画的墙线。
2. **共线邻墙跳过**：同方向延续的墙不裁剪，否则会把整条侧线误判为"在邻墙内"。
3. **交给 LISP 画**：裁剪结果以局部坐标四元组 `(x1,y1,x2,y2)` 列表传入 `(aa:wall p1 p2 thick sides)`，LISP 只负责落图元。
4. 中心线不再落到图纸上（v0.3.2）：它只用于面积/量距等语义计算，块内不画，避免在门窗洞口处留下一条穿洞的直线。

几何构造类算法（求交、面积、闭合判定）仍在 LISP；这条纯线性代数的"显示裁剪"放在驱动层，理由是它需要一次性看全所有邻墙，而 LISP 侧拿不到属性数据。

### 9.9 `AA_ROOT`：逻辑墙号

切断后同一道墙会有多个物理分段。为不破坏"`AA_ID` 在图纸内唯一"的约束（§4.2），分段各用唯一 `AA_ID`，另设 `AA_ROOT` 记录原始逻辑墙号：

- 新建墙：`AA_ROOT` = 自己的 `AA_ID`。
- 切断出的各段：`AA_ROOT` = 被切墙的原 `AA_ID`。
- 按一道墙查询：取 `AA_ROOT` 相同的一组参照；按物理段查询：直接认 `AA_ID`。

门窗的 `AA_WALLID` 记录的是**物理段**的 `AA_ID`（洞口依附于具体墙段，不依附逻辑墙），切断时驱动层会把洞口迁移到所在分段并同步改写 `AA_POS`。

### 9.10 破坏性操作的安全措施

`split` 会删除并重建全部墙体与门窗，属于破坏性操作，因此：

1. 动图前把图纸复制为 `*.bak.dxf`；
2. 期间任何异常都用备份整体覆盖回去，再抛出原因；
3. 成功后才删除备份。

同时"整网重建"保证不会出现半新半旧的中间状态。

### 9.11 墙体合并的落地（v0.3）

合并与切断共用同一套"整网重建"管线（§9.8、§9.10），差别只在段表怎么算：

1. **分组**：默认按 `AA_ROOT` 把物理分段归到同一逻辑墙；也可由调用方显式给出墙编号集合。
2. **成链**：以端点相接（距离 ≤ 容差）串成一条首尾贯通的链；链要两端都延伸到底，剩余段排不进去即视为"不成链"，该组跳过。
3. **共线校验**：链上每段方向必须与链方向平行同向，且起点到链首点的垂距 ≤ 容差。不满足则不改图（显式指定时报错，自动聚合时静默跳过）。
4. **属性收敛**：墙厚必须一致（不一致拒绝）；`AA_AX1/AA_AX2` 按端点位置从链的首末端段继承；`AA_ROOT` 置为新编号本身。
5. **洞口换算**：洞口中心到所属分段起点的距离，加上该分段起点到合并后墙起点的投影长度，得到新 `AA_POS`；换算后越界即拒绝。
6. 合并同样先备份、再动图，异常整体回滚；切点消失后墙线裁剪结果同步重算，图上不留接缝。

合并与切断互为逆操作：`split` 后立即 `merge`，编号、长度、门窗位置全部回到切断前（`tests/test_merge.py` 即为该往返的验收）。

### 9.12 墙身开洞的落地（v0.3.1）

早期版本只在洞口位置画门窗符号，墙两侧线仍是连续的，视觉上等于"贴图"而非开洞。现改为真实开洞：

1. **洞口的缺口由墙块承担**：`wall_sides()` 新增 `holes` 参数（局部 X 的 `[from, to]` 区间），与邻墙裁剪一起参与侧线求补集，缺口即天然形成。
2. **门窗落盘后重建所属墙**：`create_opening` 在校验通过、门窗块插入完成后，调用 `rebuild_wall_with_openings()` 读出该墙全部洞口区间并重生成墙块（复用 `_apply_layout` 的备份/回滚）。
3. **批量重排时同步**：`split`、`merge` 在计算新墙侧线时同样带上 `holes`，所以切墙或并墙之后洞口缺口不会丢失（`test_split.py` / `test_merge.py` 各自断言了缺口位置）。
4. **验收方式**：`block_geometry()` 直接解析 DXF 文本取块内线段，测试断言"两侧线只在洞口与邻墙重叠之外存在"。例如 6000 长墙 + 门 1000@1500 + 窗 1800@4500，实测侧线为 `[0,1000]`、`[2000,3600]`、`[5400,6000]`，与洞口区间严格互补。

### 9.13 转角合角（v0.3.2）

只做裁剪只解决了"墙线穿进邻墙"，转角处还会留下半个墙厚见方的缺口：外侧墙线停在对方中心线，没走到对方外墙面。

规则：

1. **判定**：自身墙的端点落在某堵垂直邻墙的实心矩形上（含边界），而该侧墙线的端点在邻墙矩形之外 —— 说明这一侧要绕过邻墙，属于转角而不是丁接。
2. **处理**：该侧墙线沿自身方向向外延伸，距离取邻墙半厚（即到达邻墙外墙面）。丁接（端点落在邻墙内部、两侧都被裁）不延伸。
3. **对称性**：两道墙各自按同一规则延伸，合角后两条外侧线在邻墙外墙面交点处相交，角部闭合。
4. **厚薄不等**时延伸量随邻墙厚度变化，仍落在外墙面上。
5. **判据容差取 0.01 mm**（`CORNER_TOL`）：墙方向由 `atan` 回算、再经块旋转落图，端点坐标会有 ~1e-5 mm 漂移；用 1e-9 的严格容差会把转角误判成"端点不在邻墙上"，出现"三个角合了、一个角没合"的不对称缺陷（实测踩到过，见 `test_corner.py` 的四墙闭环用例）。

### 9.14 规整时机（`normalize_around`）
墙体侧线依赖邻墙，所以"画完一堵墙"必须让受影响的墙一起重算，否则新墙与旧墙的裁剪/合角不一致。

- `normalize_around(wall_id)`：重建该墙 + 所有与它矩形相交的墙（SAT 分离轴判定），只动这一圈，不做全图重建。
- CLI 的 `wall` 命令在创建后立即调用它，返回结果里的 `normalized` 是被重建的墙数。
- `create_opening` 只重建洞口所属墙；洞口不影响邻墙的裁剪。
- `split` / `merge` 本来就是整网重建，无需额外调用。

因为每次重建都是"删旧块 → 建新块"，门窗参照独立存在、不受影响，不会丢洞。

### 9.15 图层可配置（v0.3.3）

图层是用户的图档标准，插件不该硬编码层名。

1. **默认层名**：`AA-AXIS`（轴线）、`AA-AXISTEXT`（轴号）、`AA-WALL`（墙体）、`AA-OPENING`（门窗）、`AA-ROOM`（房间名）、`AA-DIM`（尺寸标注）。
2. **覆盖方式**：项目根的 `aa_layers.json`，或环境变量 `AA_LAYERS_FILE` 指向的 JSON；键固定为 `axis / axistext / wall / opening / room / dim / sheet / title / table`，值可以是层名字符串，也可以是对象覆盖颜色/线型/线宽（详见 §15）。查找顺序：显式路径 > 环境变量 > 项目根文件；文件缺失则用默认，不报错。
3. **生效范围**：驱动层 `ensure_layers()` 按配置建层；LISP 侧通过 `(setq aa:*lay-* ...)` 在每次调用前覆盖，块内几何落在配置的层上。两处必须同时生效，否则会出现"块在自定义层、块内线仍在默认层"的裂缝。
4. **验收**：`test_layers.py` 用自定义配置（`AXIS / WALL / OPEN` 等）建轴网 + 墙 + 门，断言层表里出现自定义层、且**不出现**任何 `AA-` 前缀层。
5. **轴线独立性**：轴线只在 `axis` 层，与墙体层完全分离，需要时可单独关闭/淡显，不影响墙线。

### 9.16 参数变更重绘（v0.4）

改参数不是"改个属性值"：墙厚变了，两侧墙面线位置、门窗洞口边线长度、邻墙的裁剪区全都要跟着变。因此变更走**整体重建**。

规则：

1. **改墙（`set-wall`）**：取值 = 旧值 + 本次显式给出的字段；厚度必须为正。既有洞口必须仍在墙段范围内，否则拒绝。
2. **重建顺序**：校验 → 备份 → 摘除该墙与其门窗 → 按新厚度重建墙块（侧线带洞口缺口）→ 门窗按原 `AA_POS` 重新落图（洞口边线随新墙厚）→ `normalize_around` 重算邻墙裁剪与合角 → 回读 `AA_THICK`/`AA_KIND` 断言 → 删备份。
3. **改门窗（`set-opening`）**：位置/宽度/类型变更前先做落位校验（宽度为正、完全落在墙段内、与同墙其它洞口不重叠），校验不过**一个字节都不动**；通过则备份 → 删旧符号 → 重建 → 所属墙缺口重排。
4. **失败即回滚**：任何一步异常都用 `.bak` 整文件恢复，绝不留半成品。
5. **可重复执行**：同样参数再执行一次，结果不变（幂等），测试断言了这一点。
6. **邻墙联动验收**：`test_modify.py` 断言——邻墙 120 厚时水平墙内面止于 3940、外面补到 4060；邻墙改 300 厚后分别变为 3850 与 4150。数值对不上就说明邻墙没重算。






## 10. 对外暴露层（MCP）

数据层之上有两层调用入口，二者共用同一套库函数，不允许各写一份实现：

| 入口 | 形态 | 用途 |
|---|---|---|
| `tools/aa_cmd.py` | 命令行，一行 JSON 输出 | 人/脚本手工调用、排查 |
| `tools/aa_mcp.py` | stdio MCP 服务器 | Agent 直连，按工具名 + JSON 参数调用 |

### 10.1 传输与协议

- stdio + newline-delimited JSON-RPC 2.0（MCP 规范），**不是** LSP 的 `Content-Length` 头。
- 支持 `initialize` / `notifications/initialized` / `ping` / `tools/list` / `tools/call`；通知不产生响应。
- 无第三方依赖，客户端以子进程拉起即可（配置样例见 `mcp.example.json`）。

### 10.2 工具契约

- 工具名与原子指令一一对应，共 25 个：`aa_new` `aa_scale` `aa_axis` `aa_axis_auto` `aa_layers` `aa_axis_bind` `aa_wall` `aa_opening` `aa_room` `aa_room_auto` `aa_split` `aa_merge` `aa_set_wall` `aa_set_opening` `aa_openings` `aa_dim` `aa_set_room` `aa_rooms` `aa_sheet` `aa_set_sheet` `aa_title` `aa_north` `aa_rescale` `aa_export` `aa_show`。
- 每个工具必须声明 `inputSchema`（JSON Schema，`required` 非空），参数里必须有 `path`。
- 返回值 = §6 校验通过后的**回读结果**（句柄、长度、角度、面积、周界、`normalized` 计数等），不得返回"已发送命令"这类未验证状态。

### 10.3 失败语义

- 业务校验失败：`isError: true`，`content[0].text` 为 `{"ok": false, "error": "<具体原因>"}`。
- 未预期异常同样如实上报（`{"ok": false, "error": "TypeError: ..."}`），绝不吞掉。
- 协议层错误（未知方法 / 缺参 / 非法 JSON）走 JSON-RPC `error`，code 分别为 `-32601` / `-32602` / `-32700`。
- 失败后图纸零残留，由 `tests/test_mcp.py` 断言（比对失败前后的构件句柄集合）。

### 10.4 线型与图层在块内的落地（v0.4）

块内几何的图层与线型都由 LISP 的 `entmake` 直接带组码，随实体数据进入块定义：

- 图层：`(8 . 层名)`，与配置层名一致；
- 线型：`(6 . 线型名)`。**实测 entmake 认组 6**（探针：`(entmake (list (cons 0 "LINE") (cons 8 "0") (cons 6 "CENTER") ...))` 落盘后 DXF 组 6 = CENTER），因此轴线用专用 `aa:mkline-lt` 直接带 `CENTER`，不需要事后再跑 `properties.set`；墙线/门窗线仍走三参数的 `aa:mkline`，线型随层（Continuous）。
- 新建图档只带 `Continuous`，所以生成轴网前必须 `linetype {"load": "*"}` 把内置线型库载入（会话内只做一次，幂等），否则图元虽写了 `CENTER`，渲染时线型表里没有该条目。

（早期版本曾假设"`entmake` 不认组 6"并改用 `properties.set` 逐句柄设置，探针证伪后已改为上面的写法；两者都保留在仓库里做过对照，最终只留 LISP 路径，少一次 CLI 往返。）

验收：`tests/test_axis.py` 断言轴块内 7 条 LINE 的 `lt` 全为 `CENTER`；`samples/mcp_demo.png` 里轴线呈点划线，穿门洞时不会被误认成墙线。

## 11. 房间名称与汇总表（v0.4）

### 11.1 房间改名：为什么必须整体重建

房间块里只有一句 TEXT 承载名称，属性只做数据载体。属性改不动 TEXT，LISP 又建不了也读不到 ATTRIB，所以没有"就地改字"的路子。可行做法只有重建：

1. 从 `AA_PTS` 取净空轮廓（2 位小数，落图漂移可忽略）；
2. 校验编号存在、旧图是否带轮廓；
3. 备份 `.bak`；
4. 删旧块参照（`delete_component`）；
5. 用旧轮廓 + 旧面积 + 旧墙环 + 新名称重新走 `_store_room`（同一条落盘管线，几何与属性同源）；
6. 回读断言：`AA_NAME` 为新值、面积与旧值差 < 1e-2、块内 TEXT 文本等于新名称；
7. 删备份；任一步异常整文件回滚。

同名时不进重建分支，直接 `changed:0` —— 否则每次重跑都会重写块句柄，下游引用（表格、标注）会莫名失效。

### 11.2 表格落地：`eattext` 为什么不合适

`eattext`（属性提取成表）在本项目里被淘汰，原因有三：

1. **列名不受控**：固定 10 列英文列名（Name / Handle / Layer / Position X / Position Y / Rotation …），中文表头做不到，和出图习惯冲突；
2. **默认尺寸极小**：整表在图里只有一小段短线，必须事后手调样式；
3. **单位不换算**：面积给的是 mm² 原值，不够阅读友好。

改为原生 `table`：

- 先 `tablestyle {name:"AA-TABLE", textHeight:180, margin:50}` 建样式并 `current:true` 切过去（`styles` 里已有就不重建，幂等）；
- 再 `table {at, rows, cols, rowHeight:340, colWidth:1800, title, header, cells}`；
- `colWidth` **只接受标量正数**，传数组直接报 `colWidth must be positive`；分列宽度靠"1 列建表 + `insertcol{width}` 加列"实现（见 §11.2 与 §3.4 汇总规则）；
- 表格内容可由 `entities` 的 `geometry.cells` 回读（`tests/test_room_modify.py` 断言标题、表头、房间名、合计都在）。

`block_geometry` 只解析块定义里的 LINE / LWPOLYLINE / TEXT / MTEXT，不覆盖 ARC 与 TABLE；表格对象一律走 `entities` 或 `tableexport` 回读。

## 12. 尺寸标注（v0.6）

### 12.1 业务规则

- **只标外墙**。判定：沿墙取 25% / 50% / 75% 三个采样点，法向两侧各探"墙厚/2 + 50"，一侧落在房间净空轮廓内、另一侧不在，即外墙；两侧都在房间内的是内墙，跳过。三个采样点都判不出（孤墙、没房间）按外墙处理，宁可标多不遗漏。
- **两道尺寸线**：洞口宽在内层（默认离墙面 9mm），墙段长度在外层（默认 20mm）。轴号圈自动排在最外侧；v0.9.6 起尺寸线会先量出轴号圈的实际外扩（`axis_keepout`），再把两条线推到圈外（详见 §20.5），不再依赖固定偏移。
- **墙段长度用墙中线两点**，`rotation` 取墙方向角（度）；洞口用"洞口两端点"，同样带 rotation，斜墙也能正确标注。
- **幂等**：每次先删 `AA-DIM` 层上已有 Dimension 再重画，重跑不叠重影。
- **样式 `AA-DIM`**：字高 250、箭头 150、界线偏移 100（1:100 出图 = 2.5mm / 1.5mm / 1mm）。默认样式的字高与箭头小到几乎看不见，不建样式就标等于没标。
- **回读验收**：生成的 Dimension 数量 = 外墙数 + 外墙洞口数；逐条比对 `geometry.measurement` 与实际墙长/洞宽（容差 0.01），并确认全部落在 `AA-DIM` 层。

### 12.2 平台坑（实测）

- `dimlinear` 不会理会当前图层，**一律落在 `0` 层**，必须事后再 `properties.set {handles, layer}` 改层。
- `dimstyle {}` 空参数查询报 `name is required`，列样式只能用 `dimstyle.list {}`；单查某样式给 `name`，返回体是 `{current, style:{...}, styles, variables}`，字高在 `style.textHeight` 而不是顶层。
- `dimlinear` 支持关联模式（`{object, at}`），但本项目用两点式（不依赖被标对象是否被后续重建替换）。

## 13. 图框 / 标题栏 / 出图（v0.7）

### 13.1 业务规则

- **图幅**按 GB/T 14689 基本幅面：A0 1189×841、A1 841×594、A2 594×420、A3 420×297、A4 297×210（mm）。
- **图框内留边**：装订边 a=25mm（在左），其余三边 c：A0/A1 取 10mm，A2～A4 取 5mm。内框左下角因此是 `(a, c)`，内框尺寸 `(幅宽 - a - c) × (幅高 - 2c)`。
- **比例**：模型按 1:1 实尺绘制，图框按"图纸 mm × 比例分母"换算。1:100 的 A3 图幅在模型里就是 42000×29700，内框 39000×28700。
- **标题栏**按 GB/T 10609.1 取 180×56mm，贴内框右下角，简化为 9 格（自下而上 12/12/20 分带）：
  - 顶带 20mm：图名（整格、字高 7mm、水平居中）
  - 第二带 12mm：工程名称（120）+ 图号（60）
  - 第三带 12mm：设计（60）+ 制图（60）+ 审核（60）
  - 底带 12mm：比例（60，自动填 `1:n`）+ 日期（60）+ 单位（60）
  - 格内标签字高 2.5mm，填值字高 4mm。
- **自动排图**：不给图幅原点时，以**全图外廓**（墙、房间、门窗、轴号圈、尺寸线、表格文字；图幅自身除外）的几何中心对齐内框中心，四周留 `margin`（默认 1500 模型单位，即 1:100 时 15mm 留白）。装不下时**直接报错**并给出"需要/可用"两组数字，提示换大图幅或调小比例——不做静默缩图。
- **图幅编号**唯一：同一编号重复创建被拒绝（提示改用 `set-sheet`）。
- **改标题栏**：保持图幅、比例、位置不变，删旧图重画，块属性同步更新；块参照始终只有一个。

### 13.2 数据存储

图幅同样走"块定义 + 不可见属性"：块名 `AA_SHEET_<编号>`，插入点 = 图幅左下角（模型坐标），块内几何以图幅左下角为局部原点。

| 属性 | 类型 | 含义 |
|---|---|---|
| `AA_TYPE` | 字符串 | 固定 `SHEET` |
| `AA_ID` | 字符串 | 图幅编号 |
| `AA_SIZE` | 字符串 | `A0`/`A1`/`A2`/`A3`/`A4` |
| `AA_SCALE` | 字符串 | 比例分母（`100` 即 1:100） |
| `AA_BIND` | 实数 | 装订边（mm，固定 25） |
| `AA_PROJECT` `AA_DRAWING` `AA_NO` `AA_DATE` `AA_DESIGN` `AA_DRAWN` `AA_CHECK` `AA_UNIT` | 字符串 | 标题栏八项内容 |

图层：图框线 `AA-SHEET`，标题栏线框与文字 `AA-TITLE`，报告表格线框与文字 `AA-TABLE`（全部可在 `aa_layers.json` 改）。

### 13.3 出图

- `export` 按输出扩展名决定格式（`png` / `svg` / `pdf`），可用 `--sheet <编号>` 自动取"图幅外框 + 5% 余量"作为导出窗口，或手工 `--window x0,y0,x1,y1`。
- 窗口宽高比最好接近 1.5（`cadcraft-cli` 的 `--export` 是等比 fit + letterbox，不裁切；窗口比 1.5 更瘦高时上下会被裁）。

### 13.4 平台坑（实测）

- `--window` 传负数必须用 `--window=-100,0,100,50` 的等号写法，否则被当成未知参数 `-100`。
- 原生 `table` 的 `colWidth` 只吃标量、`insertcol` 加列后列宽不受控，文字会溢出到邻列；因此报告表格改为**纯几何**（线框 + 居中文字）绘制，列宽/行高按图纸 mm 精确控制。
- `table` 的 `at` 是**左上角**，表向下生长；几何绘制沿用同一语义。
- 轴号方向按 GB/T 50001：竖向轴线编数字 1、2、3，横向轴线编字母 A、B、C（早期版本写反了，v0.7 已纠正，`AA_VER` / `AA_HOR` 也随之交换）。

## 14. 轴网自动（v0.8）

### 14.1 业务规则（图面口径）

- 输入是**已画好的墙**：只看墙中心线，不看洞口、房间、标注。
- 分类：`rotation_rad % π` 判定方向——`|sin| ≤ 1e-3` 视为水平墙，取 `p1.y` 作为一根横轴；`|cos| ≤ 1e-3` 视为竖直墙，取 `p1.x` 作为一根纵轴；其余角度是斜墙，**跳过**并记入 `AA_SKIP`，不投影成轴线（避免把斜墙误当正交轴）。
- 同轴墙段聚类：同方向坐标线排序后，相邻差值 ≤ `tol`（默认 50mm）归为一簇，取簇均值作为轴位。这样 6000 与 6004 这种几毫米的手抖不会长出两根轴。
- 编号按 GB/T 50001 与天正习惯：纵轴（`AA_VER`）从左到右编 **1、2、3…**；横轴（`AA_HOR`）从下到上编 **A、B、C…**（超过 26 根自动续 `AA`、`AB`）。
- 轴线范围：每根轴线从**最外轴**外扩 `ext`（默认 2400，1:100 出图 = 24mm）到另一端外扩 `ext`；轴号圆（半径 400，直径 8mm）与轴线端**相切**，纵轴圈贴在 `y_max + ext + 400`，横轴圈贴在 `x_min − ext − 400`。
- 轴线必须落在 `AA-AXIS`、轴号落在 `AA-AXISTEXT`，线型强制 `CENTER`——回读逐条核对，不是"发完命令就算成功"。

### 14.2 数据存储

块名 `AA_AXGRID_<id>`（与等距轴网同前缀，`AA_MODE` 区分来源）：

| 属性 | 含义 |
|---|---|
| `AA_TYPE` | 固定 `AXGRID` |
| `AA_ID` | 轴网编号，如 `AX001` |
| `AA_MODE` | `AUTO`（自动）/ `EVEN`（等距，`create_axis_grid` 写入时省略） |
| `AA_XCOUNT` / `AA_YCOUNT` | 纵轴 / 横轴根数 |
| `AA_XPOS` / `AA_YPOS` | 实际轴位，`0.00;6000.00;10800.00` 形式、两位小数，供回读与后续吸附用 |
| `AA_VER` / `AA_HOR` | 编号序列 `1;2;3` / `A;B` |
| `AA_SKIP` | 被跳过的斜墙编号，`;` 分隔（空串表示没有） |

### 14.3 回读校验与拒绝

- 生成后立即 `block_geometry()` 回读：线数 = `XCOUNT + YCOUNT`、圆数 = 同值、文字集合 = `VER ∪ HOR`、`layer_of_block()` 取到的图层集合 ⊆ {`AA-AXIS`, `AA-AXISTEXT`}、每条线的线型都是 `CENTER`；任一项不符即抛 `CadError`，图纸零残留。
- 同名块已存在直接拒绝（"轴网 AX001 已存在"），不静默覆盖——轴网是用户画图基准，误覆盖等于毁图。

### 14.4 已知边界（本轮未做，等用户拍板）

- 只做"由墙反推轴"（先墙后轴）；"先给轴网、让墙吸附到轴"（先轴后墙）尚未实现。
- 斜墙只跳过不投影；圆弧墙/多段墙不参与。
- 与 `create_axis_grid` 共用 `AA_AXGRID_<id>` 命名空间，靠 `AA_MODE` 区分，若同一编号既想等距又想自动需换编号。

## 15. 图层规格（v0.9）

### 15.1 为什么层必须由插件建

天正的体验是"画墙就自动有层、层色层线型都是对的"，用户从不需要手调。要做到同样效果，插件必须在**每一次绘制前**保证两件事：层存在、层规格对。只 `layer.new` 建个空层不够——老图纸里的层常被人改成全白实线，画上去就失去制图分层语义。

### 15.2 标准规格表

| 键 | 默认层名 | 颜色（ACI） | 线型 | 线宽 mm | 依据 |
|---|---|---|---|---|---|
| `axis` | `AA-AXIS` | 1 红 | `CENTER` 点划线 | 0.15 | GB/T 50001 细线；轴用点划线，天正默认红色 |
| `axistext` | `AA-AXISTEXT` | 1 红 | Continuous | 0.15 | 轴号与轴线同色 |
| `wall` | `AA-WALL` | 7 白 | Continuous | 0.35 | 剖切墙线取线宽组粗线 b |
| `opening` | `AA-OPENING` | 4 青 | Continuous | 0.18 | 门窗细线；天正门窗层青色 |
| `room` | `AA-ROOM` | 7 白 | Continuous | 0.18 | 房间名文字细线 |
| `dim` | `AA-DIM` | 3 绿 | Continuous | 0.15 | 尺寸细线；天正标注绿色 |
| `sheet` | `AA-SHEET` | 7 白 | Continuous | 0.70 | 图框线取最粗的 b 级 |
| `title` | `AA-TITLE` | 7 白 | Continuous | 0.25 | 标题栏内格中线 |
| `table` | `AA-TABLE` | 7 白 | Continuous | 0.18 | 表格细线 |
| `name` | `AA-NAME` | 7 白 | Continuous | 0.25 | 图名文字/比例/指北针 |

### 15.3 落地方式

- `Session.ensure_layers()`（无参 = 全部 11 层）：先按需 `linetype {"load":"*"}` 载入 `CENTER`；读 DXF 层表判断缺层/规格不符；缺则 `layer.new {color, linetype, lineweight}`，不符则 `layer.set {color, linetype, lineweight}`；最后**再读一遍层表逐项比对**，不符抛 `CadError`。
- 每个 `create_*` / `set_*` 入口都先走这一步（原有 `session.ensure_layers([层名])` 调用点全部自动获得新行为），所以"画的时候就建好、改坏就纠回"是默认行为，不是可选优化。
- `new_metric()` 建完图立刻把 11 层备齐，Agent 后续调用不需要额外建层。
- `layers out.dxf` 只读展示现状 + 标准规格；`layers out.dxf --fix` 对老图批量矫正。MCP 对应 `aa_layers {path, fix}`。
- 层表读取不用 CLI 的 `info().layers`：它只回颜色名（`Red`/`White`）且不回线宽；改成直接解析 DXF `TABLES/LAYER` 记录（组 2 层名、62 颜色、6 线型、370 线宽×100）。

### 15.4 配置覆盖

`aa_layers.json`（或 `AA_LAYERS_FILE`）里值可为字符串或对象：

```json
{"axis": {"name": "AXIS", "color": "红", "linetype": "CENTER", "lineweight": 0.25},
 "wall": "WALL"}
```

颜色接受 ACI 数字 1–255，或 `red/yellow/green/cyan/blue/magenta/white/black/gray` 与对应中文名。自定义层名不在标准表内时，给中性规格（白、Continuous、0.18），不猜标准。

### 15.5 已知边界

- 实体颜色/线型是 `ByLayer`，所以预览与打印按层显示；但 **CADCraft 导出的 PNG 预览不渲染线宽**（已实测 0.7 与默认画出来一样细），线宽只在 DXF（组 370）与 CAD 打印时生效。要让 PNG 也看到粗墙，需要另做一道预览渲染，暂未实现。
- 门窗仍共用 `AA-OPENING` 一层（与天正"门窗同层"的习惯一致），未拆 `DOOR`/`WINDOW`；若要拆，`opening` 键可扩展为两个。

### 15.6 PNG 预览补线宽（v0.9.1）

CADCraft 的 `--export png` 不画线宽（0.7 与默认一样细，已实测），但打印/审图必须看得见粗细。做法是在导出后由 `emphasize_lineweights()` 补一遍：

- **换算**：CLI 导出是"等比 fit 不裁切"，所以像素比取 `min(W/窗宽, H/窗高)`，并居中补黑边；`px_per_mm = fit × 比例`（比例从 `AA_SHEET` 的 `AA_SCALE` 取，无图幅按 1:100，也可显式传 `scale`）。
- **只补粗线**：遍历 `AA_` 块参照，把块内图元按 `_insert_tf` 变换到世界坐标，取该图元图层在 DXF 层表里的线宽，≥ 0.20mm 才重画，像素宽 = `round(线宽mm × px_per_mm)`，颜色取图层 ACI。
- **不改 DXF**：补粗只作用于 PNG；DXF 组 370 的层线宽仍是打印依据。PDF/SVG 交给 CLI 原生输出，不补。
- **幅面线与图框线分家**：`AA-BORDER`（0.15，图幅外框/纸张边界）与 `AA-SHEET`（0.70，图框线、标题栏外框）分开，符合 GB/T 14689"幅面线细、图框线粗"；标题栏分格线仍在 `AA-TITLE`（0.25）。
- 开关：`export(..., lineweights=False)` 可关；测试见 `tests/test_layer_style.py` 第 5 段（同一张图开/关补粗，亮像素 3844→65316）。

## 16. 轴网与墙的绑定（v0.9.2）

### 16.1 语义

- 墙的属性 `AA_AX1` / `AA_AX2` 表示**起点/终点所在的轴线编号**：横墙两端沿 X 走，所以对应纵轴 `1/2/3`；竖墙两端沿 Y 走，对应横轴 `A/B/C`。
- 斜墙不套轴号（同 `auto_axis` 跳过斜墙的口径），避免把 45° 墙硬挂到某根正交轴上。
- 端点找不到 `tol`（默认 50mm）以内的轴就留空，不硬套最近的轴。

### 16.2 自动回填

- `auto_axis()` 生成轴网后立即调用 `bind_walls_to_axis()`，把全部墙的轴号写进去，返回值里带 `ax_bound` 与 `walls: [{wall, ax1, ax2}]`。
- `axis-bind` 子命令 / MCP `aa_axis_bind` 可对已有图补做；`--only-empty` 只填空值，保留用户手填的轴号。
- 写入用 `attedit {handle, values}` **就地改属性**，不重建墙块——墙线、洞口、邻墙裁剪、房间轮廓都不受影响（对比 `set_wall` 是整块重建）。

### 16.3 先轴后墙（吸附）

- `create_wall(..., snap_axis=True, snap_tol=300)`：先读图上轴网，把每个端点的 x / y 分别吸到最近的轴坐标（各自独立，互不影响），差值超过 `snap_tol` 不吸。
- 吸附结果在返回值 `snapped: {p1, p2}` 里如实给出；没吸到就不出现该键。`--snap-axis` / MCP `snap_axis` 默认关闭，避免误改用户输入。
- 吸附只发生在画墙这一步，已有墙不会被追着改（要改墙位仍是重建一整段墙）。
- 画完墙若图上有轴网，会自动补 `ax1/ax2`（`only_empty` 语义），所以"先轴后墙"一路画下来轴号是自洽的。

### 16.4 平台注意

- `attedit` 需要块参照句柄，用 `Session.component_handle("AA_WALL_", id)` 取；属性标签大小写不敏感。
- 墙端点回读有 ~1.5e-5 mm 漂移，判断"在轴上"必须用容差（默认 50mm 足够，也兼容 6000 与 6004 的合轴场景）。

## 17. 图面符号：图名标注 / 指北针（v0.9.3）

### 17.1 图名标注

- 语义：`AA_TYPE=TITLEMARK`、`AA_KIND=TITLE`、`AA_TEXT`（图名）、`AA_SCALE`（`1:100` 文本），块名 `AA_SYM_<编号>`。
- 制图规格（1:100 出图）：图名 5mm（500 图元单位）、比例 3.5mm（350）；图名下画一条粗线（落 `AA-SHEET`，0.70），比例下画一条细线（落 `AA-NAME`，0.25），符合 GB/T 50001 图名注写习惯。
- 文字宽度按 `0.9 × 字高 × 字符数` 估算（`aa:text-w`）：不使用 `ascii` 等未实测通过的函数；中英文混排时下画线长度会有 ±10% 偏差，属可接受范围。
- 插入点是图名文字左下角基线；调用方自己决定放在图下方还是标题栏上方。

### 17.2 指北针

- 语义：`AA_TYPE=TITLEMARK`、`AA_KIND=NORTH`、`AA_R`（半径），块名同为 `AA_SYM_<编号>`。
- 规格：细实线圆，直径 24mm@1:100（默认 2400 图元单位，可 `size` 覆盖）；指针为等腰三角形，尖端在圆周上方，尾部宽 3mm（总宽 = 直径/8）；顶部注 `N`（3.5mm）。
- 三角用 **3 条 LINE** 拼成，不用 LWPOLYLINE：预览补线宽阶段对多段线只按首末点重画，会画成"L 形"（已踩坑）。

### 17.3 平台注意

- 两个符号都先 LISP `entmake` 几何、再 `attdef` 定义不可见属性、`block` 归集、`insert` 落参照，几何坐标直接写成绝对坐标、块基点取 (0,0)，与墙/门窗/房间一致。
- 同类编号重名直接拒绝（`块定义已存在`），不会覆盖已有符号。
- `aa_title {path,id,at,name,scale}`、`aa_north {path,id,at,size}` 为 MCP 入口，共 23 个工具。

## 18. 标注比例联动（v0.9.4）

### 18.1 口径

"图上注记的纸面尺寸恒定"：所有注记的字高、圈径、箭头都按 **mm × 比例分母** 换算成图元单位。
1:100 时 2.5mm 文字 = 250 图元单位；改成 1:50 后同一条注记是 125，出到纸上仍是 2.5mm。

| 注记 | 纸面 mm | 1:100 | 1:50 | 来源 |
|---|---|---|---|---|
| 轴号圈直径 | 8 | 800 | 400 | `annot_size(4, n)` ×2 |
| 轴号字高 | 3 | 300 | 150 | `annot_size(3, n)` |
| 轴线外伸 | 24 | 2400 | 1200 | `annot_size(24, n)` |
| 轴号圈与轴线端间隙 | 4 | 400 | 200 | 与半径相等才相切 |
| 房间名 / 面积 | 2.5 / 2 | 250 / 200 | 125 / 100 | `aa:*room-h*` / `aa:*room-area-h*` |
| 门窗编号 | 1.8 | 180 | 90 | `aa:*label-h*` |
| 尺寸字高 / 箭头 / 界线偏移 | 2.5 / 1.5 / 1 | 250 / 150 / 100 | 125 / 75 / 50 | `dimstyle AA-DIM` 每次重设 |
| 尺寸线离墙中心线 | 20 / 9 | 2000 / 900 | 1000 / 450 | `annotate` 默认值 |
| 图名 / 比例 | 5 / 3.5 | 500 / 350 | 250 / 175 | `aa_symbol.lisp` |
| 指北针直径 | 24 | 2400 | 1200 | `create_north_arrow` |

### 18.2 比例从哪来

- `drawing_scale(session)`：优先 `AA_CFG_SCALE` 图档标记（`scale --set` 写入），其次 `AA_SHEET_*` 的 `AA_SCALE`（create_sheet 写入）；都没有按 1:100（天正默认）。
- `session.annot_scale` 可临时覆盖：`rescale` 与把比例显式传给创建函数的场景走这里。
- 所以两种顺序都对：先画标注再套图框（图框比例覆盖后续新建）、先套图框再画标注（直接读图框）。

### 18.3 `rescale` 做什么

`rescale_annotations(session, scale)` 不改任何墙/门窗几何参数，只"删组件 → 按原属性在新比例下重画"：

1. 轴网：按 `AA_XPOS/YPOS/VER/HOR` 重画轴线与轴号圈（轴位与编号原样保留）；
2. 门窗：按属性重画编号，顺带重排所属墙的洞口边线；
3. 房间：按 `AA_WALLS` 重建房间名文字（面积/轮廓由墙重算，数值不变）；
4. 图名/指北针：按 `AA_ATX/AA_ATY` 定位、`AA_TEXT` 文字重画，图名比例文字改成新比例；
5. 尺寸：`annotate(scale=...)` 先清 AA-DIM 层再按新字高箭头重画。

### 18.4 已知边界

- 房间面积表/门窗表已构件化（v0.9.5，见 §19），`rescale` 会按属性里的标题/表头/数据/列宽原样重画，字高与行高同步按 mm 规格。
- 轴网等距模式的 `AA_XSPACE` 等原始参数在重画时归一为 `AA_XPOS/YPOS`（数值等价，不再区分 EVEN/AUTO）。
- `rescale` 对斜墙轴号不补（同 v0.9.2 口径）。

## 19. 表格构件化（v0.9.5）

### 19.1 语义

- 块名 `AA_TABLE_<编号>`（自动编号 `T001` 起），`AA_TYPE=TABLE`，与墙/门窗/房间一样是块参照 + 不可见属性。
- 属性：`AA_TITLE`（表名）、`AA_HEADER`（表头，`~` 分列）、`AA_ROWS`（数据行，`@@` 分行、`~` 分列）、`AA_WIDTHS`（列宽 mm×比例）、`AA_ATX/AA_ATY`（左上角定位）、`AA_SCALE`（建表时的比例）。
- 几何仍是纯线框 + 居中文字（不用原生 `table`，它的列宽不受控），落在 `AA-TABLE` 层。

### 19.2 比例规格

行高 4mm、字高 2.5mm、表名 1.25 倍字高；都按 `mm × 比例` 换算。
1:100 时行高 400、字高 250（与旧版一致，历史图不变形）；1:50 时行高 200、字高 125。

### 19.3 换比例重画

`rescale_annotations()` 遍历 `AA_TABLE_` 参照：读属性 → 删块 → 按 `列宽 × 新比例/旧比例` 重画，行列内容与表名原样保留。
这样 1:100 画好的两张表，`rescale --scale 50` 后仍贴在原位、纸上字号不变。

### 19.4 平台注意

- 表格数据用 `~` / `@@` 分隔而不是 JSON：属性值最终写进 DXF TEXT，JSON 的引号与换行在块属性里不可靠。
- 重名直接拒绝（`表格 T001 已存在`）；`rooms/openings` 每次出表都是新编号，需要固定编号时传 `table_id`。

## 20. 图档出图比例（v0.9.6）

### 20.1 语义：先定比例，再画构件

天正的口径是"先定出图比例，图里所有按 mm 注写的东西按它换算"，而不是画完再改。
本插件把比例做成**图档级标记**：块 `AA_CFG_SCALE`，只有一条不可见属性 `AA_SCALE`（`"%.6g"` 存数值，如 `50`），**不画任何几何**，块参照放在 (0,0)。

写入入口 `set_drawing_scale(session, scale, rescale=True)`：

- 无标记 → 建块（`attdef` + `block`）再 `insert {attribs}` 落参照；已有标记 → 直接 `attedit` 改属性值，不重建块。
- 返回 `{scale, changed, handle, rescaled}`：`changed=1` 表示标记真的变了，比例相同则 `changed=0` 且不写盘。
- 图里已有注记时，默认先 `rescale_annotations` 整批重画，再写标记；`rescale=False` 只改标记（新画的东西按新比例，旧注记不动）。

### 20.2 比例解析顺序

`drawing_scale(session)` 依次取：`session.annot_scale`（临时强制，仅内部 rescale 用）→ `AA_CFG_SCALE` → 图上 `AA_SHEET` 的 `AA_SCALE` → 100。
因此"开图定比例""画完套图框""事后改比例"三种顺序都能自洽，且都不会把 1:50 的图画成 1:100 的字。

### 20.3 各入口的默认比例

轴号圈/轴号字/轴线外伸、房间名与面积、门窗编号、尺寸字高箭头界线、图名/比例、指北针、表格行高字高，全部缺省走 `drawing_scale`，显式传 `scale` 才覆盖。
`create_sheet(scale=None)` 同理：省略比例就按图档比例出图框，标题栏里的"比例"格子与图名标注不会自相矛盾。

### 20.4 图幅自动选型

`create_sheet(..., size="AUTO")`：按 `drawing_extent + 2×pad`（默认 pad 1500mm）在 A4→A0 里挑**第一个装得下的**；A0 都装不下时抛 `CadError`，提示调小比例或拆图。
显式指定图幅（含 `at` 自动排图）时，如果装不下，则从指定尺寸往上逐级升，取第一个装得下的，结果里回传 `promoted: "A4→A3"`；`at` 是人工指定位置时不升级（位置固定，升级会错位），仍报错。

### 20.5 尺寸两道 / 轴号圈的排布（天正口径）

天正的做法是：**尺寸线贴近墙，轴号圈在最外**，两者分处不同"带"，谁都不压谁。

- 两道尺寸都从**墙中心线**起算：洞口宽 9mm（内道）、墙段长 20mm（外道）。从中心线而不是墙外皮起算，是为了让 20mm 是固定的纸面距离——墙厚 240 在 1:50 是 4.8mm、在 1:100 是 2.4mm，若从外皮起算，换比例后尺寸文字会被顶进轴号圈。
- 轴号圈与轴线端点相切，圆心在 `ext + r` 处，所以圈体占 `ext → ext+8mm`。
- `auto_axis` 保证 `ext ≥ 20mm + 2mm`：给得太小时自动抬到 22mm 并在结果里回传 `ext_adjusted`；缺省仍是 24mm（1:100 → 2400），这样 20mm 的尺寸线与 2.5mm 的字高都落在圈内侧。

### 20.6 与 rescale 的关系

`rescale` 保留为补救路径（老图、甲方临时改比例），正常流程优先 `new --scale` / `scale --set`。
两者共用同一套 mm 规格表，所以同一个比例下"先画"和"后改"出来的图元尺寸必须一致——`tests/test_scale.py` 与 `tests/test_scale_pre.py` 分别覆盖这两条路径。

## 21. 房间名称 + 面积（v0.9.7）

### 21.1 图面

天正建房间默认在房间中央注两行：上一行房间名、下一行面积。这里照做：

- 名称 2.5mm，基线在形心上方 `0.75 × 名称字高`；
- 面积 2.0mm，基线在形心下方 `1.1 × 面积字高`；
- 面积文字由 LISP 用 `rtos(area/1e6, 2, 2) + "㎡"` 生成（净面积按 mm² 计算、按 m² 注写，两位小数）；
- 两行都落在 `AA-ROOM` 层，仍是 `AA_ROOM_<编号>` 块内 TEXT，不画房间轮廓线（轮廓与墙内表面重合，画出来会被误读成墙线）。

### 21.2 可选与回读

- `create_room(..., show_area=True)`；`--no-area` / MCP `show_area=false` 只注名称（有的工程只在名称表里出面积）。
- 开关存进属性 `AA_AREA_SHOW`（`1`/`0`），`rescale` 与 `set_room` 重建时按属性还原，不会因为改比例或改名把面积注记弄丢。
- 面积值本身不重算：重建走已存的 `AA_PTS` 轮廓，`AA_AREA` 必须与重建结果一致（`test_room_modify` 断言）。

### 21.3 验收

- `test_room`：块内两个 TEXT，第一个是名称，第二个以 `㎡` 结尾；
- `test_room_modify`：改名后 `texts[0]` 变、`texts[1]` 仍是面积；

## 22. 图面符号：标高 / 索引 / 剖切 + 图面自检（v0.9.8，B1）

### 22.1 三种符号的图面规格（mm，按出图比例放大）

| 符号 | 几何 | 文字 | 落层 |
| --- | --- | --- | --- |
| 标高 | 等腰直角三角，高 3，底边向右引出 1.6×高 的短基线 | 数值 2.5，写在基线**上方**（基线 y + 0.55 字高） | 三角+基线 `AA-SHEET`，数值 `AA-NAME` |
| 索引 | 圆直径 10 + 水平直径线 | 上半详图编号、下半图号，均 2.5 | `AA-NAME` |
| 剖切 | 位置线只画两端两段 6 的粗线（不与图面线条相接），两端各 5 的方向线 | 编号 `no-no` 2.5，两端都写 | 线 `AA-SHEET`，编号 `AA-NAME` |

- 标高值统一走 `format_elevation`：`0 → "±0.000"`、`3.6 → "3.600"`、`-0.45 → "-0.450"`（米制、三位小数、不带 m；`-0.0004` 归一成 `±0.000`）。
- 索引同图详图写 `—`（`sheetno` 默认值）。
- 剖切编号按投射方向对齐：左右投射时贴端部外侧，上下投射时居端部上方/下方；两端都写同一个编号。
- `p1/p2` 是剖切位置线的两个端点，落在建筑轮廓外一点；`direction` 是投射方向（看哪边），`down/up/left/right`。

### 22.2 存储

`AA_SYM_<编号>` 块参照，属性：

- 共有：`AA_TYPE=SYMBOL`、`AA_ID`、`AA_KIND`、`AA_ATX/AA_ATY`、`AA_SCALE`；
- ELEV：`AA_VALUE`（格式化后的文字）、`AA_H`（三角高）；
- INDEX：`AA_DETAIL`、`AA_SHEETNO`；
- SECTION：`AA_NO`、`AA_DIRX/AA_DIRY`、`AA_X1/Y1/X2/Y2`、`AA_SEG`（位置线单段长）。

`rescale` 按属性重建三种符号（锚点/编号/方向/剖切端点都不变，只换 mm→图纸单位）。

### 22.3 audit（图面自检，只报不改）

`audit(session, tol=1.0)` 返回 `{issues, count, by_kind, errors, scale}`，issue 含 `kind/level/message/handles/detail`：

| kind | level | 判据 |
| --- | --- | --- |
| `wall_endpoint` | error | 墙端点既没对上别的墙端点，也没落在别的墙身上（T 接） |
| `opening_outside` | error | 洞口 `pos±宽/2` 越出所属墙段 |
| `room_text_overlap` | warn | 两个房间块的文字包围盒相交 |
| `dim_over_axis` | warn | 尺寸文字中点落在轴号圈 `r + 字高/2` 内 |
| `outside_sheet` | error | 图形外廓超出图幅**内框**（insert 点即内框左下角，用 `inner_w/inner_h` 判） |

`errors` 只数 error 级；CLI `audit --strict` 在 `errors > 0` 时返回 1，可挂进批处理。

## 23 柱（column，v1.0.0）

柱按"图例符号 + 语义属性"存进块定义，块名 `AA_COLUMN_<编号>`，编号全图唯一（与轴号、门窗号同规则：重复即拒绝，零残留）。

### 23.1 图形构成

| 类型 | 图层 | 图元 | 说明 |
|---|---|---|---|
| `rect` 矩形柱 | `AA-COLUMN`（灰 8 / CONT / 0.35） | 1 个 `SOLID`（实心填充）+ 1 条闭合 `LWPOLYLINE`（外框） | 填充让柱在平面图上"实"起来，与墙体涂黑习惯一致；外框保证缩小后仍可见轮廓 |
| `circle` 圆柱 | `AA-COLUMN` | 1 个 `CIRCLE`（D=直径）+ 24 个退化四边形 `SOLID`（扇形填充） | CADCraft 的 HATCH entmake 返回 nil（已验证不可行），只能用退化 SOLID 逼近 |

- **尺寸是真实尺寸**（毫米），不随出图比例缩放——柱是结构实体，不同于轴号圈/文字这类"纸上尺寸"，因此 `rescale` 只管注释类构件，不重画柱；
- 矩形柱可转角 `AA_ANGLE`（度），填充与轮廓按同一旋转矩阵一次性算出，避免填充与轮廓错位；
- 柱的定位点是**柱心**（`at`），与天正"插柱于轴线交点"一致；转角柱仍以柱心为旋转中心。

### 23.2 属性（ATTRIB，全部 invisible）

| 属性 | 值 | 用途 |
|---|---|---|
| `AA_TYPE` | `COLUMN` | 构件类型分流 |
| `AA_ID` | 编号，如 `GZ1` | 全图唯一句柄 |
| `AA_KIND` | `RECT` / `CIRCLE` | 形状 |
| `AA_W` / `AA_H` | 宽 / 高（mm） | 矩形柱；圆柱 `AA_W=AA_H=直径` |
| `AA_ANGLE` | 旋转角（度，`-180..180` 归一） | 矩形柱朝向 |
| `AA_MATERIAL` | 材料，默认 `CONCRETE` | 出材料表用 |
| `AA_AREA` | 面积（mm²，矩形 `W*H`、圆柱 `πD²/4`） | 直接回读，不再二次计算 |
| `AA_ATX` / `AA_ATY` | 柱心坐标（mm） | 与原图坐标比对，容忍 ~1e-5 漂移 |

### 23.3 拒绝条件（图纸零改动）

- 编号为空、或与已有构件重名；
- `kind` 不在 `rect/circle`；
- 尺寸 ≤ 0（矩形任一方向、圆柱直径）；
- 属性回读与入参不一致（`AA_AREA` 按 2 位取整比对）。

### 23.4 验收

- `test_column`：矩形 400×300 → 面积 120000 mm²、1 SOLID + 1 LWPOLYLINE；圆柱 D500 → 196349.5 mm²、24 SOLID + 1 CIRCLE；转角 30° 可回读；重名/错类型/非正尺寸三类拒绝；
- `demo_full`：四个外墙转角各落一根 240×240 构造柱（GZ1–GZ4），`audit` 仍为 `0 {}`（柱不被误判为墙端悬空或压字）；

## 24 台阶 / 散水（step / apron，v1.0.0）

两者都是"室外附属"，同落 `AA-STEP`（白 7 / CONT / 0.18），块名 `AA_STEP_<ID>`、`AA_APRON_<ID>`。

### 24.1 台阶

- 局部坐标：原点在**贴墙线中点**，`+Y` 为外挑方向；插入时按 `angle`（外挑方向角，度，0=+X / 90=+Y / 270=-Y）转成块旋转 `angle-90`。
- 图形：贴墙那条线**不画**（与墙线重合，画了就是双线）；只画
  - `steps` 条踏步线，等距在 `y = k*tread`（k=1..steps），最后一条即外轮廓线；
  - 两侧边线：`x=±w/2`，从 `y=0` 到 `y=steps*tread`。
- 总进深 `depth = steps*tread`，总高 `h = steps*rise`（`rise` 单步高，默认 150，平面不画，记录给剖面/材料表用）。
- 尺寸是真实尺寸，不随出图比例缩放；`rescale` 不碰它。

### 24.2 散水

- 局部坐标同上（原点贴墙线中点，`+Y` 外挑）。
- 图形三条线：外沿线 `y=width`（`x=-len/2..len/2`）+ 两端收头 `x=±len/2`（从 `y=0` 到 `y=width`）；贴墙线由外墙自己承担。
- 外挑宽默认 800，常用 600–1000；**两端收头暂为垂直收头**，阳角 45° 斜接、阴角八字口未做（ROADMAP 备注）。
- 与尺寸线的配合：第一道尺寸线离墙中心 900（@1:100），所以散水取 600 时外沿 720，落在尺寸线内侧，不会压线；取 800 会压到第一道尺寸线，出图时需把尺寸线外移或改 600。

### 24.3 属性（ATTRIB，全部 invisible）

| 属性 | STEP | APRON |
|---|---|---|
| `AA_TYPE` | `STEP` | `APRON` |
| `AA_ID` | 台阶号，如 `ST1` | 散水号，如 `SW1` |
| `AA_W` | 台阶宽（沿墙） | 外挑宽 |
| `AA_STEPS` / `AA_TREAD` | 踏步数 / 踏步宽 | — |
| `AA_DEPTH` | 总进深 = steps*tread | — |
| `AA_RISE` / `AA_H` | 单步高 / 总高 | — |
| `AA_LEN` | — | 沿墙长 |
| `AA_ANGLE` | 外挑方向（度） | 外挑方向（度） |
| `AA_ATX` / `AA_ATY` | 贴墙线中点 | 贴墙线中点 |

### 24.4 拒绝条件（图纸零改动）

- 编号为空或与已有块重名；
- 台阶宽 / 踏步宽 / 散水长 / 散水宽 非正实数；
- 踏步数不是 >=1 的整数。

### 24.5 验收

- `test_step`：台阶 1500 宽 3 步 300 → 5 条线（3 踏步 + 2 侧边）、y 序列 `0/300/600/900`、`AA_DEPTH=900`、`AA_H=450`；散水 6000×800 → 3 条线；重名/零宽/2.5 步/负踏步宽四类拒绝；

## 25 MCP 事务编排（v1.0.2）

原子工具保持"一次一件事"，多步操作靠三个事务工具兜住：

### 25.1 `aa_batch(path, ops, rollback=True)`

- `ops = [{tool, args}, ...]`，`args` 没写 `path` 时继承外层 `path`；
- 顺序执行，全部成功返回 `{ok: true, done, results}`；
- **任一失败**：把图纸还原成调用前的字节（原本不存在就删掉），返回
  `{ok: false, failed_index, failed_tool, error, done, rolled_back}`；
- `rollback=false` 可保留已成功部分（仅用于明确要"半成品"的场景）。

### 25.2 `aa_checkpoint(path, label)` / `aa_restore(path, snapshot)`

- 快照落在同目录 `.aa_snap/`，文件名 `<图名>-<时间戳>[-标签].dxf`，返回 `id`；
- `restore` 接受 `id` 或绝对路径，字节级覆盖回图纸；
- 快照不自动清理（`.aa_snap/` 已进 `.gitignore`），需要时手工删。

### 25.3 验收

- `test_mcp_batch`：3 步批量成功；第二项洞口越界 → `failed_index=1`、字节与调用前一致；快照改图后 `restore` 字节一致；快照不存在时明确报错。

## 26 楼梯（stair，v1.0.3 第一版：直跑 + 双跑）

块名 `AA_STAIR_<ID>`，本地原点 = **起步踏步前缘中点**，`+Y` 为上行方向；插入旋转 = `angle - 90`
（`angle` 是上行方向角，90=向上、0=向右、270=向下）。落 `AA-STAIR`（白 7 / CONT / 0.18）。

### 26.1 直跑 STRAIGHT

- 两条梯段边线 `x=±w/2`，`y=0..steps*tread`；
- `steps` 条踏步线，等距 `y=k*tread`（k=1..steps，最后一条就是上端边线）；
- 起步线（`y=0`）**不画**——它通常就是墙线/平台边，画了会双线；
- 上行箭头：中心线上一条杆 + 实心三角头（长 300、半宽 70，真实毫米）；
- 起步处写"上"字，字高 2.5mm@出图比例，横向写、偏离箭头杆 220mm，块转 180° 时补 180° 防倒字。

### 26.2 双跑 U 形 DOGLEG

- 总宽 `W = 2w + well`，总深 `D = 2*landing + steps*tread`；
- 外轮廓 4 条（左右侧 + 上下端），上下平台分界 2 条（`y=landing`、`y=landing+run`）；
- 梯井两侧边线 2 条（`x=±well/2`，只在梯段段内）；
- 两跑踏步线各 `steps` 条（同一组 y，方向相反），合计 `2*steps` 条；
- 左跑上行箭头（+Y），右跑下行箭头（−Y），各一个实心三角头；
- 左跑起步处写"上"字（同直跑规则）。

### 26.3 属性（ATTRIB，全部 invisible）

| 属性 | 含义 |
|---|---|
| `AA_TYPE` / `AA_ID` / `AA_KIND` | `STAIR` / 编号 / `STRAIGHT` 或 `DOGLEG` |
| `AA_W` | 单跑梯段宽 |
| `AA_STEPS` | **每跑**踏步数 |
| `AA_STEPS_TOTAL` | 总踏步（直跑=steps，双跑=2×steps） |
| `AA_TREAD` / `AA_RISE` | 踏步宽 / 踏步高 |
| `AA_RUN` | 单跑水平投影 = steps*tread |
| `AA_DEPTH` | 楼梯总进深（直跑=run，双跑=2×landing+run） |
| `AA_WELL` / `AA_LANDING` | 梯井宽 / 平台深（直跑记 0） |
| `AA_ANGLE` | 上行方向角（度） |
| `AA_ATX` / `AA_ATY` | 起步点坐标 |

### 26.4 拒绝条件（图纸零改动）

- 编号为空或重名；
- `kind` 不在 `STRAIGHT/DOGLEG`；
- 梯段宽或踏步宽非正实数；
- 每跑踏步数 < 2 或非整数；
- 双跑时梯井宽为负、平台深 ≤ 0。

| `FIRST` 首层 | 只画上行的第一跑（全宽踏步），顶端 45° 剖断，不画上部平台与第二跑；标"上" |

2. **"上/下" 竖排**：文字旋转 90°，沿梯段方向排，位置在轮廓下方左侧（原来横排、贴在梯段里）。
3. **折断线改成折断符号**：四条短斜线组成的"Z"形缺口，虚线层 `AA-STAIR-BREAK`（DASHED），两端各伸出梯段边线 0.4 踏步；中层横切上行跑，止于梯井边不再侵入第二跑。
4. **首层几何**：左短右高的斜切（左边界高 `0.42*梯段长`、右边界通高），踏步只画斜线以下，只有上行箭头 + "上"。
5. **顶层**：两跑全画、两跑都有贯穿杆，只在下行跑（第二跑）0.30 处放向下箭头 + "下"。

§26.9 的四层配色不变。`test_stair` 期望值随几何更新（中层 32 线、首层 10 线、顶层 28 线）。

### 26.11 箭头改成天正式的"绕一圈"（v1.0.8）

天正的楼梯箭头不是两条独立直线，而是**一条折线**：第一跑起步处向上 → 到上平台横穿到第二跑 → 沿第二跑下来，整条看起来像 "n"。

- 折线：`(xl, -0.12run) → (xl, dep-0.25平台宽) → (xr, dep-0.25平台宽) → (xr, -0.12run)`
- 两个箭头分别落在两跑中部（上行 0.55 处朝上、下行 0.45 处朝下）；
- 首层只有一跑，仍是一条向上折线 + 单箭头；顶层同样走 "n"，只在第二跑带向下箭头。

### 26.12 楼梯文字方向（v1.0.10，修正）

把天正预览放大到 10 倍后发现之前的判断是错的：天正"上/下"是**水平正字**，不是竖排。
（当初那两张 20 像素的图看起来像竖排，是因为把"下"的横画当成了竖画。）

现在：文字水平正字，位于梯段轮廓下方、箭头杆右侧 `0.6 字高` 处，随楼梯整体角度旋转（180° 方向时用反字）。

### 26.13 双跑平面去掉下平台空框（v1.0.12）

天正的双跑楼梯平面只画**一个休息平台**（图上端、两跑之间的那一段），起步那一端直接就是最后一条踏步线，不再套一个空矩形。原来我们两端各画一块平台，下面多出一个大空框，看起来像"框套框"。

现在：
- 进深 `dep = 梯段长 + 平台宽`（原来 `2×平台宽 + 梯段长`）；
- 轮廓只到起步踏步线 y=0，上端到 `run+平台宽`；
- 平台分界线画在 `y = run`；
- 梯井两条竖线从 `y = -0.08×梯段长`（伸出轮廓）画到 `y = run`，跟天正一样探出个头；
- `AA_DEPTH` 随之改为"梯段长+平台宽"。

### 26.14 梯井画成"跑道"形（v1.0.13）

天正的梯井不是两条竖线，而是**一条闭合的窄长圆角框**（两端小圆角，上下都探出梯段轮廓）。
原来我们画两根竖线、两头开口，看着像"两条栏杆"。

现在 `aa:well` 生成一条闭合 `LWPOLYLINE`：两侧竖边 + 上下各两个 45° 倒角（0.55×井宽/2），
范围 `y = -0.08×梯段长 ～ 平台线 + 0.3×井宽`，图层仍在 `AA-STAIR`。

## 27 楼层表（v1.0.14，B6 第一项）

### 27.1 为什么先做它

立面、剖面都要回答"这栋楼有几层、每层多高、地面在哪、每层对应哪张平面图"。这些数据在纯平面图里没有载体，所以先落一张**楼层表**，作为立剖的数据源。

### 27.2 数据口径

| 列 | 含义 | 示例 |
|---|---|---|
| 层号 | 层序号，屋面可写"屋面" | 1 / 2 / 3 / 屋面 |
| 楼层标高 | 该层地面标高（m，三位小数，零写 ±0.000） | ±0.000 / 3.600 / 7.200 |
| 层高 | 该层层高（mm） | 3600 |
| 平面图号 | 对应的平面图纸编号 | 建施-01 |
| 层名 | 中文层名 | 首层 / 二层 / 女儿墙 1200 |

- `elev` 省略时按层高自下而上累加，首层默认 ±0.000；也可显式给（地下层用负数）；
- 校验：层高必须 > 0；第 n 层标高必须高于第 n-1 层、且不低于第 n-1 层顶（否则层高与标高对不上）；表编号不能重复。

### 27.3 存储与回读

- 表体用 `draw_table` 画（线框 + 居中文字，行高 4mm、字高 2.5mm、列宽按纸面 mm 乘以比例）；
- 包成 `AA_TABLE_<编号>` 块，`AA_TYPE` 改写为 `FLOOR_TABLE`，行数据存 `AA_ROWS`（行 `@@` 分隔、列 `~` 分隔）；
- `read_floors(session, id)` 把表反解成 `[{no, elev, height, plan, name}]`，立面/剖面直接吃这个列表；
- CLI：`floors <dxf> <id> --at=x,y --floor="1,3600,建施-01,首层" ...`，`--show=<id>` 只回读；
- MCP：`aa_floor_table`，`floors` 传 `[{no, height, plan, name, elev?}]`。

### 27.4 验收

`test_floor`：三层 3600/3600/3300 → 标高 ±0.000 / 3.600 / 7.200、总高 10500、顶标高 7200；`read_floors` 反解一致；显式负标高可覆盖；层高 0、标高低于下层顶、编号重复三类拒绝。

## 28 屋顶平面（v1.0.15，B6 第二项；v1.0.29 补女儿墙 + 上人孔）

### 28.1 图面口径（GB/T 50104 + 天正"屋顶"）

屋顶平面图表达屋面形状、坡向、檐沟与雨水口，不画立面高度。四类做法：

| 类型 | 图元 | 用途 |
|---|---|---|
| FLAT 平屋顶 | 檐口外轮廓 + 檐沟内线 + 四角雨水口（方篦子）+ 南北两条找坡箭头 | 多/高层常用 |
| GABLE 双坡 | 檐口外轮廓 + 正脊（贯到两端檐口），坡屋面不注找坡箭头 | 条状、坡屋顶 |
| HIP 四坡 | 檐口外轮廓 + 正脊 + 四条 45° 斜脊，坡屋面不注找坡箭头 | 低层别墅/宿舍 |
| SHED 单坡 | 檐口外轮廓 + 低端檐沟 + 单向找坡箭头 | 雨篷、单坡屋面 |

- `at` = 屋面投影（建筑外轮廓）左下角，宽沿 +X、进深沿 +Y；
- 檐口外挑 `overhang`（默认 600）、檐沟 `gutter`（默认 300）；
- 找坡箭头一律**尖指下坡**（檐口 / 檐沟），杆长按屋面对角一半自动取，箭头半宽 0.7 倍字高；
- 雨水口为 300×300 方框 + 中横线，布置在檐沟四角（天正默认位置）；
- 四坡正脊长度 = 长短边之差（矩形四坡标准做法），斜脊起于檐口外角。

### 28.2 构件属性

`AA_TYPE=ROOF`、`AA_ID`、`AA_KIND`（FLAT/GABLE/HIP/SHED）、`AA_W`、`AA_D`、`AA_OVERHANG`、`AA_GUTTER`、`AA_RIDGE`（X/Y）、`AA_ANGLE`、`AA_AREA`（**含外挑的水平投影面积**）、`AA_ATX/ATY`；
块名 `AA_ROOF_<编号>`，块基点 = `at`，可整体旋转。

### 28.3 校验

- 屋面宽/进深必须 > 0；外挑 ≥ 0；檐沟 > 0；
- 平屋顶要求 `2×(外挑+檐沟) < min(宽, 进深)`，否则"屋面已经没有净面积"；
- 女儿墙厚 ≥ 0 且只在 FLAT 上画（GABLE/HIP/SHED 给了直接拒绝）；`2×厚 < min(宽,进深)`；
- 上人孔边长 > 0，方框四边必须落在屋面净区（平屋顶净区从 `外挑+檐沟` 或女儿墙厚算起），出界拒绝。
- 类型只能是四类之一；屋脊方向只能 X/Y；编号重复拒绝。

### 28.4 验收（test_roof）

6000×4000 两侧各外挑 600 → 7200×5200 = 37.44 m²。图元数：平屋顶 6 多段线（轮廓/檐沟/4 雨水口）+ 6 直线（4 篦子横线 + 2 杆）+ 2 实心箭头；双坡 1/1/0；四坡 1/5/0；单坡 2/1/1。v1.0.29 增 RF6：平屋顶 + 女儿墙 240 + 上人孔 700 → 9/7/2 + 1 注字（多出 2 条女儿墙闭合线、1 个上人孔方框、1 条对角斜线）。

## 29 建筑立面（v1.0.16，B6 第三项；v1.0.28 补檐口板厚 + 轴号；v1.0.30 补三道竖向尺寸）

### 29.1 数据来源

立面不吃平面里的墙线，而是吃**楼层数据 + 门窗清单**：
- `floors` = 自下而上 `[{height, elev?, no?, plan?, name?}]`，可直接喂 `read_floors` 的结果；
- 标高缺省按层高累加，首层 ±0.000；
- 门窗 `[{floor, x, w, h, sill, kind}]`：`x` 是洞口左边距（沿立面宽），`sill` 是窗台高（相对本层楼面）。

也可以只给墙号让它自己取：`wall="W001"` 时调 `read_facade_openings` 把平面上这道墙的
`AA_OPENING` 反解成上面那份清单，再和手填的 `openings` 合并（常用做法：一层门窗由平面
派生，二三层仍有差异时手补）。`flip=True` 用于这面墙在平面上是从右往左画的（如朝北的
外墙），此时 `x = 墙长 - AA_POS - 洞宽`，否则门窗整排会左右颠倒。CLI 对应
`--from-wall=W001 [--flip]`，MCP 对应 `wall` / `flip`。

"从平面自动投影取数"这条路已经通了，只是**只取 x 与宽高**：平面洞口不记立面标高关系，
窗台高仍要在平面 `create_opening(sill=…, height=…)` 里给准，否则立面会退回 `sill=0`。

### 29.2 图面口径（GB/T 50104）

| 图元 | 画法 |
|---|---|
| 地坪线 | 粗实线，两端各出头 5mm |
| 两侧外轮廓 | 粗实线，从 ±0.000 到女儿墙压顶（无女儿墙时到檐口/山墙） |
| 楼面线 | 细实线，每层一条（首层与地坪线重合不重复画） |
| 门窗 | 天正立面做法：洞口矩形 + 窗框双线（四周内缩 60）+ 上部亮子横线（600 或洞高 1/3 取小）+ 竖向中梃分扇（每 1.2m 一格，至少两扇）+ 窗台线（比洞口每侧宽 60）；门为洞口 + 门框 + 双扇中缝（宽≥900），窄门画门扇上冒头线；门扇高固定 2100，**洞高 >2200 才画门上亮子线**（2100 的门再画一条横线就成了窗） |
| 平屋顶 | 女儿墙与外墙同宽，顶部一条压顶线 + 一条内细线（不做挑檐，避免立面长"大帽子"） |
| 双坡 GABLE | 正对山墙：檐口水平线 + 左右两条坡线交汇成正脊（脊高 `rise`） |
| 双坡 EAVE | 正对檐口（脊与图面平行）：檐口线 + 屋脊线 + 两端竖边，不出现山墙三角 |
| 檐口板厚 | `eave=h`（0=不画）：FLAT 无女儿墙的挑檐、GABLE、EAVE 都在檐口线下再画板底线 + 两端封口（拍平在 `top-h`） |
| 立面轴号 | `axes=[{x,label}]`：顶部外 8mm 细实线圆（圈内 3mm 字）落在轮廓顶上方 4mm 引线端；立面不画通长轴线，只留短引线，免得和门窗线打架 |
| 标高 | 每层右侧距轮廓 8mm 处一个标高符号（三角尖对着楼面线，数字在其右上）；右端有轴号时整列再右移 4 个圆半径,免得三角压圈 |
| 竖向尺寸（v1.0.30） | `dims=True`（默认）左侧三道尺寸线，距墙内皮 9/16/23mm：内道「细部」= 窗台高/洞高，中道「层高」= 各层高 + 女儿墙或脊高，外道「总高」= ±0.000 到女儿墙压顶/脊顶。尺寸界线从 x=0（墙内皮）起，量值取起止端点 y 差，全部落 `AA-DIM`（3 号色 0.15）。小于 5mm（=500）的分界点会被并到下一段：不同洞口的窗台/洞顶错开时会造出 300 这类无意义杂段，注上去文字会骑到相邻尺寸上 |

### 29.3 属性

`AA_TYPE=ELEVATION`、`AA_ID`、`AA_W`、`AA_FLOORS`、`AA_ROWS`（`层号~标高~层高` 用 `@@` 换行）、`AA_TOP`（屋面标高）、`AA_TOTAL`（含女儿墙/脊高总高）、`AA_ROOF`、`AA_PARAPET`、`AA_RISE`、`AA_OVERHANG`、`AA_OPENINGS`、`AA_AXES`（轴号用 `;` 连）、`AA_EAVE`、`AA_ANGLE`、`AA_ATX/ATY`；块名 `AA_ELEVATION_<编号>`。

### 29.4 校验

- 立面宽 > 0；层高 > 0；标高必须递增；
- 洞口层号在 1..层数；`x∈[0,width]` 且 `x+w<=width`；`sill>=0`；`sill+h<=层高`；
- **同层洞口不得水平+竖向同时重叠**（叠了就是错图）；
- 屋顶类型 FLAT/GABLE/NONE，双坡必须给正脊高；编号重复拒绝；
- 檐口板厚 ≥ 0，`roof=NONE`（没有檐口）时给正数直接拒绝；
- 轴号 `x∈[0,width]`、编号非空，越界或空号拒绝。

### 29.5 验收（test_elev）

3 层 3600/3600/3300、宽 6000、平屋顶女儿墙 1200 → 顶 10.500、总高 11.700、7 个洞口（94 线 + 3 文字，门 9 线：洞口 4 + 门框 4 + 中缝 1）；双坡 1800 → 总高 12.300（37 线 + 5 文字）。v1.0.28 增 E4：无女儿墙挑檐 + 檐口板厚 200 + 轴号 1/3 → 23 线 + 5 文字（3 标高 + 2 轴号）。各类拒绝各跑一次。

v1.0.30 补三道竖向尺寸与**位置断言**：E1（3 层 3600/3600/3300 + 女儿墙 1200）新增 14 条 Dimension
（内道 9 段 900/1200/1200/1500/900/1500/900，中道 3600/3600/3300/1200，外道 11700）；断言
`3600` 出现 2 次、`3300`/`11700`/`1500` 存在，且每条 `layer==AA-DIM`、`defpt.x<0`（在墙外侧）、
`|p14.y-p13.y| == measurement`。E6 守 `dims=False` 不新增任何尺寸。LINE/TEXT 计数不变（94/3、37/5、23/5）。

平面↔立面的口径另由 `test_link` 守（v1.0.23）：`AA_POS` 是**洞口中心**到墙起点的距离，
所以左边距 = 中心 − 半宽：南墙（起点在左手边）派生 `x=1050/4250`、北墙 flip 后 `x=1000`、
不 flip 为 `x=5000`；`wall=` 合并时 2 樘平面洞口 + 1 樘手填 = 3 樘。

## 30 建筑剖面（v1.0.17，B6 第四项；v1.0.31 补尺寸）

### 30.1 图面口径

剖面只吃楼层数据（与立面同一份），竖向剖切表达楼板与屋面构造：

| 图元 | 画法 |
|---|---|
| 地坪线 | 粗实线，两端出头 5mm |
| 外墙（被剖到） | 剖切面穿过两端外墙，**两端都按墙厚画窄带**（外皮 x=0、内皮 x=外墙厚；另一端在宽-墙厚..宽）；剖到门窗时墙线断开 |
| 半剖（可选） | `side="LEFT"/"RIGHT"` 只画那一端的墙带，另一端画一条内表面细线，且该端不接受洞口 |
| 剖到的门窗 | 洞口上下封口 + 窗框双线（内缩 60）+ 玻璃竖线（窗）或门上亮子线（门）+ 窗台板向室内挑 60；`side` 指明落在哪一端 |
| 楼板 | 每层楼面一条板顶（粗）+ 一条板底（细，下返板厚 100），画在两端墙带之间净宽内 |
| 室内隔墙（被剖到） | `inner_walls=[{x, thick, openings?}]`：x 从剖面左端室内面起算，画同宽窄带贯穿到墙顶；带 `openings` 时按洞口断墙（薄墙也画洞口上口 + 门扇冒头线）；压在外墙上、彼此重叠、洞口叠高都拒绝 |
| 梁 | `beams=[{floor, x0, x1, h}]`：挂在那一层楼板底，画两条梁侧线 + 梁底线；首层不能挂梁、x1 必须大于 x0 |
| 楼梯断面 | `stairs=[{floor, x0, x1, treads}]`：从 floor 层楼面爬到上一层，踏步逐级画"一平一竖"（踏步宽 = 跑长/级数、踏步高 = 层高/级数），再加一条梯段板斜线（板厚取楼板厚）与两端收头；踏步数 <2、楼梯出净宽都拒绝 |
| 墙身分界 | 板底到板顶之间的两道竖线（细），保持墙体剖面连续 |
| 平屋顶 | 屋面板（板底细 + 板顶粗）+ 女儿墙：两端各画窄矩形 + 压顶线 |
| 双坡 | 屋面板底与板顶各两条斜线，交汇成正脊（脊高 `rise`） |
| 标高 | 各层楼面 + 屋面，右侧 8mm 处 |
| 尺寸（v1.0.31） | `dims=True`（默认）左侧三道竖向（口径同立面：洞口/层高/总高，落 `AA_DIM` 层）+ 底部两道横向：内道注内皮到内皮的分段（`wall..width-wall`，再叠隔墙与楼梯的 x 区间）、外道注总宽 `0..width`。剖面总高含 100 屋面板，中道那一段是"板厚+女儿墙"（10500→11800 = 1300）。墙厚 240 在 1:100 只有 2.4mm，横向细部**不注**，交给 `AA_WALL` 与墙身详图；横向细部里**段长 < 15mm（1.5m）的不注**——`dimlinear` 的文字锚点不由我们控制，窄房间 1.1m 净空的四位数会骑到相邻尺寸上，宁可不注 |

剖面门窗可以直接从平面反取，不用手抄：`read_cut_openings(session, p1, p2)` 沿剖切线
（p1=图上左端、p2=右端对应的平面点）找被切到的墙，再判切点是否落在洞口宽度内，
