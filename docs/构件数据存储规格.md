## 33 楼层复制 / 标准层（v1.0.34，B7 第三项）

### 33.1 为什么是"复制"而不是"阵列"

学校、宿舍、办公楼这类多层工程，二~N 层平面往往与"标准层"几乎一样：差几道隔墙、差一个
设备平台。人工再画一遍既慢又容易漏门窗。天正的做法是"标准层/层间复制"：选源层构件、给目标
层号、可选平移，生成后仍可逐件改。我们照这个口径做 `copy_floor`，**一次调用生成一整层**，
不做参数化阵列（阵列一旦改源层不会联动，反而更难维护）。

### 33.2 规则

- 只复制**带 `AA_FLOOR` 属性**的构件：墙、墙上的门窗、房间；
- 楼梯 / 柱 / 台阶 / 散水目前**没有层号属性**，不复制（否则会跨层乱跑）。要复制它们，先给这些
  构件补 `AA_FLOOR`，再扩 `copy_floor`，文档与测试同步改；
- 门窗、房间的编号统一加前缀（`2W001` / `2M001` / `2R001`），宿主墙编号同步换到新墙；
- 房间围合墙全部换成新层墙号，**面积必须与源层一致**（不等就报错，说明围合关系错了）；
- `offset` 只做整体平移（`(0, 9000)` 把整层挪到上方 9m，便于同图并排核对），不改变构件尺寸。

### 33.3 校验（六类拒绝）

| 情况 | 报错关键词 |
|---|---|
| 源层与目标层相同，或任一 <1 | 相同 |
| 源层没有任何墙 | 没有墙 |
| 目标层已有墙（避免叠图） | 已有墙 |
| 新墙编号与图上已有构件冲突 | 冲突（提示给 `prefix`） |
| `offset` 不是两个数 | 偏移 |

### 33.4 返回字段

`{ok, src, dst, offset, walls, openings, rooms, counts{walls,openings,rooms}, skipped_openings, skipped_rooms}`；
编号列表按图元顺序返回（调用方断言请先排序）。`skipped_*` 说明"为什么没带过来"（如"宿主墙不在源层"
"围合墙不在源层"），不静默丢构件。

### 33.5 接口

- 库：`copy_floor(session, src_floor, dst_floor, offset=(0,0), prefix="")`；
- CLI：`copy-floor <dxf> --from 1 --to 2 [--offset 0,9000] [--prefix 2]`（原地改图，回 JSON）；
- MCP：`aa_copy_floor`（`path/from/to/offset/prefix`，工具数 45，`SERVER_INFO` 1.0.34）。

### 33.6 未做

楼梯/柱/台阶/散水的层号与复制；跨图幅复制（把标准层复制到另一张图框里，现在只能同图平移）；
"标准层"概念（一次复制到 2..N 层，需要循环调用）；复制后自动补楼层表行（现需 `floors` 手工登记）。

### 33.7 验收（test_floor_copy）

一层 7200×4500 四墙 + 一门一窗一房间 → 复制到 2 层（offset `(0,9000)`、prefix `2`）：4 墙 2 门窗
1 房间，墙/门窗/房间编号均带 `2`，房间面积 21657600 mm² 与源层一致，围合墙换成 `2W00x`；
重复复制到 2 层被"已有墙"拒绝；1→3 再复制成功；五类非法参数各自拒绝；CLI `copy-floor` 与库一致。
样例 `tools/demo_floor_copy.py`：一层平面 + 整层复制出的二层平面（同图上下并排，窗/门/房间标注一致）。


## 34 详图：详图符号 + 门窗大样（v1.0.35，B7 第四项）

### 34.1 为什么先做这两样

前 33 节把"平面/屋顶/立面/剖面/门窗表/图纸集/楼层复制"补齐后，一套建施还差"放大到能施工"的图：
门窗大样（每樘洞口的分格与尺寸）、墙身节点、卫生间/楼梯间详图。其中**门窗大样**是唯一能完全由已有
数据自动生成的——洞口宽、高、窗台高、编号都在图上，画法也最规整，先把它做扎实；详图符号顺带补齐，
这样平面上的索引符号（v1.0.21 已有）能指向具体的详图。

### 34.2 详图符号

| 项 | 取值 | 说明 |
|---|---|---|
| 圆直径 | 14mm（1:100 → 1400 图元） | 索引符号 10mm，详图符号 14mm，GB/T 50001 |
| 上半 | 详图编号（如 1） | 与平面上的索引符号编号对应 |
| 下半 | 图纸号 | 同一张图上写 "—" |
| 字高 | 4mm | 常用 3.5~5mm，取 4 |

`AA_SYM_<编号>`，`AA_KIND=DETAIL_MARK`，`AA_DETAIL/AA_SHEETNO/AA_DIAM` 可回读；`read_detail_mark`。

### 34.3 门窗大样（关键：放大倍数）

我们只有模型空间一个比例（1:100 出图），没有布局/视口，所以 **1:20 的详图只能把几何放大 5 倍来画**：

- `factor = 出图比例 / 详图比例`（1:100 出 1:20 → 5；1:50 → 2）；
- 几何（洞口、框、扇、墙垛、窗台板、放大后的坐标）一律乘 `factor`；
- 注字、尺寸线偏移、图名**不乘**——它们按纸面 mm 算（1:100 时 2.5mm 字 = 250 图元），
  这样放大后打印出来仍是 2.5mm 字、8mm 尺寸线间距；
- 尺寸数字写**真实洞口尺寸**（1500 / 1500），不是放大后的 7500——所以尺寸是自绘线 + 文字，
  不用 `dimlinear`（后者按坐标量，会量成 7500）。

画法：洞口轮廓 + 两侧墙垛（默认 240 深，上下各多画 300）+ 门窗框（60）+ 中梃（60，宽≥1200 加）+
亮子（窗高≥1800 加，高 600）+ 双扇中缝（门宽≥900 加）+ 每格玻璃再内缩 40 画扇框 + 窗台板
（窗：挑出 60、厚 100）；尺寸 2 道（洞口宽、洞口高）；图名 "C1515 窗大样" + "1:20" 画在块内。

`AA_OD_<编号>`，`AA_TYPE=OPENING_DETAIL`，存 `AA_REF`（源洞口）/`AA_NO`/`AA_KIND`/`AA_W`/`AA_H`/
`AA_SILL`/`AA_FACTOR`/`AA_RATIO`/`AA_TITLE`，`read_opening_detail` 回读；`at` 是洞口左下角。

### 34.4 校验

| 情况 | 报错关键词 |
|---|---|
| 大样编号重复 | 已存在 |
| 既没给洞口编号也没给门窗编号 | 必须指定 |
| 洞口编号不存在 / 门窗编号不存在 | 没有洞口 / 没有编号 |
| 同一门窗编号在图上有多樘 | 多樘（必须给具体洞口编号） |
| 详图比例 ≤0，或放大倍数 ≤0 | 比例 / 倍数 |
| 图上没有门窗洞口 | 没有门窗洞口 |

### 34.5 接口

- 库：`create_detail_mark / read_detail_mark`、`create_opening_detail / read_opening_detail`；
- CLI：`detail-mark <dxf> <id> --at x,y --detail 1 [--sheet 建施-03] [--show=<id>]`；
  `opening-detail <dxf> <id> --at x,y (--opening D001 | --no C1515) [--ratio 20] [--factor n]
  [--wall-depth 240] [--title ...] [--no-dims] [--show=<id>]`（共 41 个子命令）；
- MCP：`aa_detail_mark`、`aa_opening_detail`（工具数 47，`SERVER_INFO` 1.0.35）。

### 34.6 未做（明确记录）

墙身节点（窗台/窗顶/女儿墙构造，需要墙身剖面与材料图例）；卫生间/楼梯间详图（需要局部重画平面 +
洁具/踏步定位）；门窗图例表；详图内的材料填充（HATCH 在 CADCraft 里 entmake 返回 nil，做不了）；
**真正的同图多比例**（现在靠"几何放大 + 文字不放大"绕过去，一张图仍只有一个出图比例，多比例混排
不能互相引用）；索引符号带引线（v1.0.21 的索引符号只有圆，没有引线）。

### 34.7 验收（test_detail）

## 35 详图：墙身节点（v1.0.36，B7 第四项续）

### 35.1 做什么 / 不做什么

做两种最常用、且能纯参数生成的墙身节点（垂直剖面，1:20）：**SILL 窗台节点**、**PARAPET 女儿墙节点**。
不做窗顶/过梁、阳台雨篷、材料分层（保温/防水/抹灰）——没有 HATCH，分层只能画线，图面反而糊；
这些留给后续单项，先不糊弄。

### 35.2 坐标约定

`at` = **墙外皮**与**室内楼面**的交点；x 正向指向室内（右），室外在左。所有构造尺寸沿这个方向排：

| 参数 | 默认 | 含义 |
|---|---|---|
| `wall_thick` | 240 | 墙厚（外皮 0 → 内皮 T） |
| `slab` | 120 | 室内楼板 / 屋面板厚 |
| `sill` | 900 | 窗台高（SILL 用，楼面到窗台板顶） |
| `parapet` | 1200 | 女儿墙高（PARAPET 用，屋面板顶到压顶底） |
| `cap` | 60 | 压顶厚 |
| `cap_out` | 60 | 压顶 / 窗台板挑出（两侧各挑） |
| `ratio` | 20 | 详图比例 1:20 |

### 35.3 画法

- **SILL**：墙身只画到窗台（`0..sill` 两道竖线）+ 室内楼板（内皮往里 1500，上下两条线 + 收头）+
  窗台板（`-cap_out..T`，厚 100，盖在墙顶）+ 窗台上方只画窗框（外皮起 60、宽 60）+ 玻璃线，
  **窗台上方不再画墙**（那是洞口）；
- **PARAPET**：墙身到女儿墙顶 + 屋面板 + 压顶（`-cap_out..T+cap_out`，厚 `cap`）；
- 尺寸：墙厚 240（SILL 注在墙底外侧、PARAPET 注在压顶之上，避开窗框/压顶线）、
  窗台高 900 / 女儿墙高 1200（外墙侧一道）；压顶厚与挑出记属性，不注（60 的尺寸线只有 3mm 长，
  字会压到相邻线）；
- 图名「窗台节点」「女儿墙节点」+「1:20」画在块内。

放大口径与 §34 一致：几何乘 `factor = 出图比例/详图比例`，注字与尺寸偏移不乘，尺寸数字写真实 mm。

### 35.4 属性与接口

`AA_WN_<编号>`，`AA_TYPE=WALL_NODE`，存 `AA_KIND/AA_WALL/AA_SLAB/AA_SILL/AA_PARAPET/AA_CAP/AA_CAPOUT/
AA_FACTOR/AA_RATIO/AA_TITLE`；`read_wall_node` 回读。

- CLI：`wall-node <dxf> <id> --at x,y [--kind SILL|PARAPET] [--wall 240] [--slab 120] [--sill 900]
  [--parapet 1200] [--cap 60] [--cap-out 60] [--ratio 20] [--factor n] [--title ...] [--no-dims]
  [--show=<id>]`（共 52 个子命令）；
- MCP：`aa_wall_node`（工具数 56，`SERVER_INFO` 1.0.51）。

### 35.5 校验

重号拒绝；`kind` 只能 SILL / PARAPET；墙厚/窗台高/女儿墙高必须 >0；板厚/压顶/挑出不能为负；
比例 ≤0 或倍数 ≤0 拒绝。

### 35.6 未做（明确记录）

窗顶（过梁）节点；阳台/雨篷节点；屋面女儿墙泛水、滴水线；材料分层与图例；节点与平面索引的编号联动；

## §36 楼梯间大样（v1.0.37，B7-4 续）

### 36.1 定位

`create_stair_detail(session, detail_id, at, stair_id, ratio=20, factor=None, title=None, dims=True, scale=None)`
把图上**已有楼梯**（`AA_STAIR_<stair_id>`）的参数读出来，按出图比例/详图比例放大重画一张平面大样。
`at` = 大样左下角，**上行方向朝上**（不沿用平面里的旋转角，详图按正向摆放）。
落块 `AA_SD_<detail_id>`，`AA_TYPE=STAIR_DETAIL`，`read_stair_detail` 回读。

### 36.2 读源 & 放大

读 `AA_KIND`（STRAIGHT/DOGLEG）、`AA_W`、`AA_STEPS`、`AA_TREAD`、`AA_WELL`、`AA_LANDING`、`AA_LEVEL`。
`factor = 出图比例 / 详图比例`（默认 1:100 / 1:20 = 5），或用 `factor` 直接给；
几何按 `factor` 放大，注字/线宽按出图比例（不跟着放大）。

**踏步总长 `AA_RUN` = 踏步数 × 踏步宽**（10×280=2800），不是楼梯总进深（双跑还要加平台深）。

### 36.3 画法

- **直跑 STRAIGHT**：`梯段宽 × 踏步总长` 矩形 + `1..steps-1` 条踏步线 + 向上箭头 + "上"字（TOP 改向下箭头 + "下"字）；箭头小三角头按纸面 5/1.8mm，不随梯段放大。
- **双跑 DOGLEG**：`(2×梯段宽+梯井) × (踏步总长+平台深)` 外轮廓 + 梯井两道竖线（0..踏步总长）+ 平台带
  （踏步总长到顶）+ 两跑踏步线 + 左跑"上"箭头 + 右跑"下"箭头（FIRST 不画下行、TOP 不画上行）；"上/下"用 4mm 字高，尺寸字高 3.2mm。

### 36.4 尺寸（真实 mm，自绘线 + 文字，不用 dimlinear）

- 梯段宽：下方水平一道，字 `1200`；
- 踏步总长：左侧竖向一道，字 `10×280=2800`（`步数×踏步宽=总长`，转 90°）；
- 平台深：双跑时右侧竖向一道（踏步总长到顶），字 `1200`。
图名默认 `楼梯间详图` + `1:20`，落在下方（`ty=-24mm`，有尺寸时）。

### 36.5 属性

| 属性 | 含义 | 属性 | 含义 |
|---|---|---|---|
| `AA_TYPE` | STAIR_DETAIL | `AA_LANDING` | 平台深 |
| `AA_ID` | 大样编号 | `AA_LEVEL` | 首层/中层/顶层 |
| `AA_REF` | 源楼梯编号 | `AA_FACTOR` | 放大倍数 |
| `AA_KIND` | STRAIGHT/DOGLEG | `AA_RATIO` | `1:20` |
| `AA_W` | 梯段宽 | `AA_TITLE` | 图名 |
| `AA_STEPS` | 每跑踏步数 | `AA_ATX/AA_ATY` | 插入点 |
| `AA_TREAD` | 踏步宽 | `AA_SCALE` | 出图比例 |
| `AA_RUN` | 每跑踏步总长 | | |
| `AA_WELL` | 梯井宽 | | |

返回 `{block,handle,id,ref,kind,width,steps,tread,run,well,landing,level,factor,ratio,title,dims,bbox,geom_handles}`；
`bbox=[-30mm, ty-6mm, 总宽+18mm, 总高+16mm]`（`ann()` 按出图比例折算）。

- CLI：`stair-detail <dxf> <id> --at x,y --stair <楼梯编号> [--ratio 20] [--factor n] [--title ...]
  [--no-dims] [--show=<id>]`（共 52 个子命令）；
- MCP：`aa_stair_detail`（工具数 56，`SERVER_INFO` 1.0.51）。

### 36.6 拒绝

重号；源楼梯不存在/类型不对；缺源楼梯编号；比例 ≤0；倍数 ≤0；梯段宽 ≤0、踏步数 <2、踏步宽 ≤0；
双跑梯井 <0 或平台深 ≤0。

### 36.7 未做（明确记录）

楼梯间墙体/门窗（大样只画梯段本体，不带梯间墙）；扶手/栏杆线；踏步防滑条；首层/中层剖断线；

## §39 基础大放脚（v1.0.42）

### 39.1 定位

`create_foundation(session, item_id, at, wall=240, steps=2, step_h=130, step_w=65, depth=2000, base=300, cover=50, beam=250, cushion_ext=50, stub=100, soil=0, lime_layer=150, rebar=True, bars=6, stirrup="Φ6@250", ratio=20, factor=None, dims=True, title=None, scale=None)`
`at` = 墙中心线与**室外地面**交点；向下画基础剖面，1:20 放大（倍数 = 出图比例/详图比例）。
按标准 **6-6（6a-6a）砖砌大放脚条基**节点：240 墙、500 基底、600 垫层、埋深 2000。
几何按局部坐标画、块插入到 `at`；块 `AA_FD_<id>`，`AA_TYPE=FOUNDATION`，`read_foundation` 回读。

### 39.2 画法

- 地面线：墙身处断开，左右各自出头，右段伸到 `±0.000` 标高符号外侧（`AA-STEP` 层）；
- 墙头：`±0.000` 以上留 `stub`（默认 100），墙边收头处画中间下凹的折断线；
- 墙顶：`cover` 砖覆盖 + 地圈梁 `beam`，圈梁底即防潮层，标高按 `-(cover+beam)` 自动算；
- 墙身：`wall` 厚两道竖线，从圈梁底到放脚顶；
- 对称放脚：每级高 `step_h`（130）、宽 `step_w`（65），逐级外放，基底 = 240 + 4×65 = 500；
- 垫层：`base` 300 厚，每边外伸 `cushion_ext` 50，总宽 600；`soil` >0 时底部按该厚度画 3:7 灰土，并按 `lime_layer` 画分层压实线，其余为 C10；
- 材料填充（CADCraft 无 HATCH，按多边形手绘）：砖砌体 45° 斜线（含墙头，按折断线裁切）、圈梁与 C10 点状骨料、灰土分层线；
- 配筋示意（`rebar=True`）：圈梁内 `bars` 根 Φ12（每侧一半），箍筋按 `stirrup` 注字，道数随梁高；
- 标高：`±0.000`、圈梁底 `-0.300`、垫层底 `-2.000`；
- 引注：`MU10 砖砌体`；梁高足够时 `stirrup` 与 `地圈梁 <beam>：<bars>Φ12` 分两条引出，梁矮时合并；
- 垫层引注：`soil=0` 时按“`3:7 灰土` / `（或 C10 混凝土垫层）`”两行标注；`soil>0` 时按实际分层分别引 `C10 混凝土垫层` 与 `3:7 灰土`。

### 39.3 尺寸

- 墙厚：墙头上方 `240`（随 `wall` 变）；
- 埋深：右侧竖向总尺寸 `2000`；
- 竖向分道：`50 / 250 / 1140 / 130 / 130 / 300`；
- 垫层宽：下方 `600`，再分 `50 / 500 / 50`。

### 39.4 属性

`AA_TYPE=FOUNDATION`、`AA_ID`、`AA_WALL`、`AA_STEPS`、`AA_STEPH`、`AA_STEPW`、`AA_DEPTH`、
`AA_BASE`、`AA_BASEW`、`AA_CUSHW`、`AA_STUB`、`AA_SOIL`、`AA_LIME`、`AA_COVER`、`AA_BEAM`、`AA_BARS`、`AA_STIRRUP`、`AA_FACTOR`、`AA_RATIO`、`AA_TITLE`、`AA_ATX/AA_ATY`、`AA_SCALE`；图名 `aa:title` 按整组宽度居中，默认“基础大放脚”。
返回 `{block,handle,id,wall,steps,step_h,step_w,depth,base,base_width,cushion_width,stub,soil,lime_layer,cover,beam,bars,stirrup,factor,ratio,dims,bbox,geom_handles}`；
`bbox=[-垫层半宽-65mm, -埋深-30mm, 垫层半宽+50mm, 墙头+12mm/2mm]`（`ann()` 按出图比例折算；`dims=False` 时顶边只留墙头+2mm）。

- CLI：`foundation <dxf> <id> --at x,y [--wall 240] [--steps 2] [--step-h 130] [--step-w 65]
  [--depth 2000] [--base 300] [--cover 50] [--beam 250] [--cushion-ext 50]
  [--stub 100] [--soil 0] [--lime-layer 150] [--no-rebar] [--bars 6] [--stirrup Φ6@250]

- MCP：`aa_foundation`（工具数 56，`SERVER_INFO` 1.0.51）。

### 39.5 拒绝

重号；墙厚 ≤0 或级数 <1；台阶高/宽/垫层 ≤0；覆盖/圈梁/外伸 <0；墙头/灰土 <0 或灰土 > 垫层；分层厚 ≤0；埋深 ≤ 放脚高+垫层+圈梁+覆盖；比例 ≤0；倍数 ≤0；配筋根数为奇数。

## §41 构件一致性检查 reconcile（v1.0.48，自动收尾扩展）

### 41.1 reconcile(session, fix=False, tol=1.0)

只扫 `AA_` 构件数据，不改几何；返回：

- `issues[]`：每条含 `kind/level/message/ref/detail/fixable/suggestion`；
- `count/by_kind/errors/warnings/fixable`；
- `suggestions[]`：有歧义、只给建议不自动改的问题；
- `components`：扫到的 `walls/openings/rooms` 数量；
- `fixed[]` 与 `rolled_back`（`fix=True` 时）。

检查项：

- `wall_zero_len` / `wall_zero_thick`：墙长或墙厚为 0；
- `opening_zero_width`：洞口宽为 0；
- `opening_orphan`：宿主墙编号在图上不存在；
- `opening_outside`：洞口区间越出墙段 `[0, 墙长]`（容差 `tol`）；
- `opening_overlap`：同一堵墙上两个洞口区间重叠；
- `room_wall_missing`：房间围合墙有编号缺失；
- `room_no_outline`：旧房间没有 `AA_PTS` 轮廓（warn，不可修）；
- `room_area`：存储 `AA_AREA` 与轮廓鞋带面积不符（容差 `max(tol, area*1e-5)`，可修）。

### 41.2 fix 只做无歧义的收尾

`fix=True` 先整图备份 `<stem>.reconcile.bak.dxf`，再按以下规则动作，任一动作失败整图回滚：

- 零长墙：无门窗、且不被任何房间引用时删除；有门窗或房间引用时只给建议（删了会制造悬空门窗/缺围合）；
- `opening_zero_width`：宽度为 0 的洞口直接删除；
- 悬空门窗：只有唯一一道“同向、起点重合、洞口放得下且不压别的洞口”的墙可挂时，删旧块并按原中心距重挂；没有或多解时只给建议；
- 洞口越界：墙长放得下、夹回墙内后不压同墙其他洞口时，平移到 `[宽/2, 墙长-宽/2]`；比墙还长或夹回会重叠时只给建议；
- 房间面积：门窗/墙体/围合墙都无遗留错误时，删旧房间块后按当前 `walls` 重跑 `create_room`；仍有门窗/墙体/围合墙错误时返回 `fix_skipped`，不硬重建。

墙厚为 0、同墙洞口重叠、房间缺围合墙/缺轮廓等“保留哪个/尺寸猜多少”不明确的情况，一律只写 `suggestion`，不自动改。

明确不做：不重建尺寸标注、门窗表、房间表、楼层表、立面、剖面；这些属于 `refresh` 派生联动，不在 reconcile 里冒充。

### 41.3 CLI / MCP

- CLI：`reconcile <dxf> [--fix] [--tol]`（共 52 个子命令）；
- MCP：`aa_reconcile`（工具数 56，`SERVER_INFO` 1.0.51）。

### 41.4 验收（test_reconcile）

6000×4000 四墙 + R001 + D001：干净图 `count=0`、`components={walls:4,openings:1,rooms:1}`；
把 `AA_AREA` 改 0 → 报 `room_area` 且 `fixable`；`fix=True` 后面积恢复 `5760×3760=21657600`；
把门 `AA_POS` 改 7000 → 报 `opening_outside`，`fix=True` 夹回 5500 且不删门；面积同时坏时按“先洞口、后房间”两项都修；
同墙两洞口重叠 → `fix=True` 不动作，只出 `suggestions`；零长墙（无门窗/无房间）自动删，有门窗只建议；
悬空门窗在唯一同向同起点墙存在时重挂成功，两个候选不硬改；洞口宽 7000 > 墙长 6000 时只建议。

## §42 本地 AI 纠错 / 确认面板（v1.0.51）

- `GET /api/preview?path=...`：调 `export()` 出全图 PNG，按图纸 mtime 缓存到 `.panel_cache/`；
- `POST /api/edit`：`{path, kind, id, fields}`，改前自动 `aa_checkpoint(before-edit)`，再按 kind 调 `set_wall` / `set_opening` / `set_room`，返回结果里带 `checkpoint`；
- `POST /api/proposal`：`{path, title, ops}`，只接受 `aa_set_wall` / `aa_set_opening` / `aa_set_room`；在临时副本上跑 `aa_batch`，返回构件 diff、新增/消除问题；
- `GET /api/proposal/preview?path=...`：导出预演副本 PNG，用于改前/改后滑杆对比；
- `POST /api/proposal/commit`：校验原图 SHA1 未变，自动 `aa_checkpoint(before-batch)`，用预演结果原子覆盖原图；
- `POST /api/proposal/discard`：整批删除临时副本，原图不动；
- `POST /api/action`：`checkpoint` / `restore` / `reconcile` / `reconcile_fix` / `audit` / `verify`；
- `GET /api/snapshots?path=...`：列 `.aa_snap/*.dxf` 最近 16 条。

路径必须在 `--root`（默认仓库根）内，且扩展名 `.dxf`；防止面板变成任意文件读取器。

### 42.2 面板能力与边界

- 只读预览，可缩放 25%–320%，可"原图"在新标签打开；支持改动前/后滑杆对比；
- 打开图纸：顶栏路径输入 + “浏览”弹窗；弹窗左侧最近 8 张，右侧根目录文件树（只列 `.dxf`，可上一级，也可直接填路径）；最近记录存 `.panel_cache/recent.json`，越界/不存在自动过滤；
- 多图纸页签：打开成功后才建页签，页签保存该图已读的 `data`、预览 URL、选中构件、缩放/对比状态、当前侧栏和滚动位置；切回时先恢复快照再请求 `/api/stat`，`mtime_ns` 或 `bytes` 不同就重读该图，未变则直接用缓存；关闭当前页签自动切到相邻一张，关最后一张回空面板；关闭只删 UI，不写 `.dxf`；
- 预览图高亮：选中构件 / 问题 / 变更差异行时，用 `view.window` 把世界坐标线性映射成百分比，在图上画 `.hl-box` 金框与 `.hl-tag` 编号；墙按两端点+墙厚，门窗按宿主墙+中心+洞口宽，房间按 `pts` 多边形；无选中或切图即清除；
- 变更集全量高亮：提案存在时默认同时画全部 `changes`，`changed` 画改前红虚线与改后金框（改前整体偏移 2px 便于重合时分辨），`added` 绿框、`removed` 红虚线；选中项加粗并置顶；`#showAllChanges` 取消后只画选中项；
- 构件树按墙/门窗/房间/其他分组，点选后给属性编辑：
  - 墙：厚/类型/材质/轴号；
  - 门窗：中心距/宽/高/窗台/类型/框厚/编号/编号侧；
  - 房间：名称（面积/周长/围合墙只读）；
- 问题清单合并 `reconcile`、`audit` 与 `verify`，点问题按 `ref` 定位构件；
- AI 变更集：Agent 通过 `/api/proposal` 提交一组构件修改，面板在临时副本上预演，显示改前/改后、新增问题、消除问题；人接受后才写入，拒绝则原图不动；
- 快照/回退走 `aa_checkpoint` / `aa_restore`，回退前二次确认；
- **不做**：画线、偏移、修剪、延伸、倒角、阵列、夹点拖动；这些仍由 CLI/MCP 的构件级命令负责。

### 42.3 AI 变更集预演

1. `POST /api/proposal` 把原图复制到 `.panel_cache/proposals/<sha1>/case.dxf`，在该副本跑 `aa_batch`；

5. 接受时先 `aa_checkpoint(before-batch)`，再把预演副本原子覆盖原图；放弃直接删临时目录；
6. 提案同时保存 `view.window` 和改后 `geometry`（墙/门窗/房间），与预演预览同一窗口、同一几何，保证差异行点出来的金框和改后图完全对齐；
7. 前端全量高亮用同一组 `view.window + geometry` 画所有 `changes`，改前取自当前 `S.data`，改后取自提案 `geometry`，不额外读写图纸。

当前只允许 `aa_set_wall` / `aa_set_opening` / `aa_set_room`，避免通过提案接口执行导出、新建、回退等副作用工具。

## §43 全图复核 verify（v1.0.49）

定位：`audit` 查图面几何压碰，`reconcile` 查构件自身自洽；`verify` 只读查“图与表对不上”，不改图，也不自动修。缺表、缺轴网按“这项没做”跳过，不把没画的表当成错误。

### 43.1 检查项

- 轴号：同一轴网内竖/横轴号不得重复；轴数必须与编号数量一致；墙的 `AA_AX1/AX2` 非空时必须能在图上轴号集合里找到；
- 门窗表：单张总表时逐行核对 `编号 + 类别 + 宽×高 + 窗台高 + 樘数 + 所在层`；漏项、多项、樘数不符是 error，层号不符是 warn；多张表只提醒、不擅自汇总；旧版 6 列门窗表按 `编号+类别+宽高+樘数` 兼容核对；
- 楼层表：层号不重复、层高为正、标高严格递增、下层顶与上层底不得重叠（重叠 error，缺层 warn）；立面 `AA_ELEVATION_*` 与剖面 `AA_SECTION_*` 的 `AA_ROWS` 必须与楼层表逐层一致；
- 尺寸：每个 `Dimension` 的 `measurement` 必须等于 `p13`→`p14` 的几何距离；同一方向、同一偏移线上的尺寸段不得重叠；同一条链的分段合计必须等于更外一道覆盖同跨度的总尺寸。

### 43.2 CLI / MCP / 面板

- CLI：`verify <dxf> [--strict] [--tol]`（共 52 个子命令），`--strict` 有 error 时返回 1；
- MCP：`aa_verify`（工具数 56，`SERVER_INFO` 1.0.51）；
- 面板：`POST /api/action {action:"verify"}`，问题清单来源 `verify`，按钮“全图复核”；结果 toast 显示 error/warn 数。

### 43.3 输出与验收

输出 `{issues, count, by_kind, errors, warnings, stats, scale}`；`issues[]` 含 `kind/level/message/ref/detail/suggestion`；`stats` 记录本次实际检查到的轴网/门窗表/楼层表/立面剖面/尺寸数量。

`test_verify` 用 12m×4.8m 三段南墙 + 轴网 + 门窗表 + 两层楼层表 + 立面 + 三道尺寸：
干净图 `count=0`；改轴号属性为重复 → `axis_label_duplicate`；加一根 `AA_AX1=9` 的墙 → `axis_wall_ref`；
加一樘表中没有的门 → `opening_table_missing`；删立面 `AA_ROWS` 一层 → `floor_source_mismatch`；
删南墙中间一段尺寸 → `dim_chain_total`；`verify` 前后文件字节不变。

## §44 总平面 site（v1.0.55，M2 第一项）

### 44.1 定位与边界

`create_site(session, site_id, boundary, buildings, roads, entrances, north, coords, dims, scale, at)` 一次生成方案级总平面：
**用地红线闭合多段线 + 建筑轮廓 + 道路双线 + 出入口箭头与名称 + 简化指北针 + 红线顶点坐标（m）+ 总宽/总深尺寸**。
红线与道路均为**方案示意**，不替代实测权属界线、市政管线或报建总图；样例图签已写明该限制。

不新增图层：红线用 `AA-AXISTEXT`（红、Continuous），建筑 `AA-WALL`，道路 `AA-STEP`，坐标/总尺寸 `AA-DIM`，出入口与指北针文字 `AA-NAME`，沿用 21 层标准。

### 44.2 坐标与画法

- `boundary`：世界坐标 mm 点列，至少 3 点；首尾重复时自动去尾；闭合多段线按给定顺序连线；鞋带面积必须 >0；
- `at`：整体平移，几何按世界坐标生成后统一加 `(atx, aty)`；
- `buildings`：`(x0,y0,x1,y1[,名称])` 矩形，或 `{pts:[...],name:...}` 多边形；轮廓闭合，名称居中；
- `roads`：`(宽度, [x,y...])` 中心线，逐段按半宽法向偏移画两条边线；宽度必须 >0；
- `entrances`：`{at:(x,y), label, dir:(dx,dy)}`，`dir` 为朝外方向（零向量拒绝）；画短箭头 + 朝外 5mm 处写名称；
- `north`：指北针位置，画 12mm 圆 + 指针 + `N`；
- 坐标注在红线**内侧**（外移 6mm 会与总尺寸线打架），文字为米制两位小数；总尺寸画在红线外侧 10mm。

注字/箭头按出图比例取纸面 mm，几何按世界 mm 1:1。

### 44.3 数据模型

块 `AA_SITE_<id>`（`AA_TYPE=SITE`），属性：

| 属性 | 含义 |
|---|---|
| `AA_ID` | 总平面编号 |
| `AA_PTS` | 红线顶点 `x,y;x,y;...`（闭合前的点列） |
| `AA_AREA` | 鞋带面积 mm² |
| `AA_DATA` | JSON：`buildings/roads/entrances/north/coords/dims` |
| `AA_ATX/AA_ATY` | 整体平移 |
| `AA_SCALE` | 出图比例分母 |

`read_site(session, id)` 把上述字段解成结构化数据（点转 `(x,y)` 元组，JSON 数组原样返回），供面板与 Agent 回读。

### 44.4 拒绝与验收

重号、红线少于 3 点、面积为 0、道路宽度 ≤0、出入口方向为零向量、比例 ≤0 均拒绝且不落盘。
`test_site` 覆盖库生成/回读、五类拒绝、CLI `--show` 与 MCP `aa_site`；`demo_site` 输出 DXF+PNG，`audit=0`，并已目检标题/坐标/尺寸/出入口/指北针无压碰。

实测坐标文件导入（如 CAD 地形图/DGN 红线）、道路交叉口圆弧、场地竖向与土方、市政管线综合、与报建总图图签的法定字段——这些需实测资料与专项设计，不在此命令内伪造。

## §45 屋面细部 roof-detail（v1.0.56，M2 第二项）

## §46 图面质量门禁（v1.0.57）

### 46.1 为什么和 `issues` 分开

`audit` 原来的 `issues/count` 是"脚本会查的几何错误"；`count=0` 只说明没有崩溃级错误，不代表图能交出去。
新增三类**质量警告**放在 `warnings/warning_count/quality` 里，不进 `count`，避免历史图纸因"图面空/注字不好"被回归判失败，同时给出可测量、可跨轮次比较的指标。

### 46.2 检查口径

| 警告 | 口径 | 阈值 |
|---|---|---|
| `title_block_overlap` | 按图幅块的 insert 点 + `sheet_layout` 算出图签矩形，逐图元求世界坐标包围盒相交 | 命中 ≥1 |
| `sheet_underfill` | 内框 24×16 网格，逐线段/文本包围盒标命中格 | 命中率 < 0.30 |
| `internal_jargon` | 扫描全部 TEXT（含图签块），命中 `AA_` / `鞋带` / `块参照` / `参数化构件` / `豆包` / `CADCraft` | 命中 ≥1 |

`quality.occupancy`（0–1）是连续指标；`quality.jargon` 是命中条数。重复文本按内容去重，最多列 8 条。

### 46.3 一次性解析

`_dxf_all_blocks()` 一次读 DXF 解出全部块定义，`_quality_pieces()` 再把块内点用 `_insert_tf` 变换到世界坐标；图幅块本身标 `frame=True`，几何检查跳过、术语检查保留。避免逐块调用 `block_geometry` 反复读整份 1MB 图纸。

### 46.4 顺带修正

`audit` 原来把图幅 `insert` 点当成"内框左下角"，实际是"图幅外框左下角"，导致 `outside_sheet` 的内框算错（左/下各偏 `a/c × scale`）。现按 `inner_org` 修正；`test_audit` 的越界用例仍通过。

### 46.5 交付图修订（低内存）

- `00_总平面索引`：图幅整体下移 10000，图签不再被红线右边线穿过；图纸目录同步下移；只重建这一张小图，不重跑 5 层。

## §47 自动排附表 place（v1.0.58）

### 47.1 为什么要有这个

手写表格坐标是整条流水线里返工率最高的一步：挪一次表要重算一次，挪歪了压图签、压轴号，而且**同一套图的各层还要各算一遍**。`place` 把"这张图上哪儿还有地儿"变成可计算的量。

### 47.2 空位搜索：`find_free_rect`

输入内框、占用外包列表、目标宽高，输出目标矩形的**左上角**（表格向下生长）。

- **网格 + 积分图**：按 `cell = max(w,h)/120` 建二维占用网格，再做二维前缀和，单次"这块矩形空不空"的查询是 O(1)。A1 整幅按 1mm 网格扫一遍也只有十万级常数查询。
- **半开区间**：点 `p` 落在第 `floor((p-origin)/cell)` 格，所以 `[a,b]` 覆盖 `floor(a)…ceil(b)-1`。这条**不是形式主义**——图签顶标高正好等于横带底标高，用 `floor(b)` 会把"恰好贴边"的框多标一整行，于是"贴图签上方"这个最好的位置永远放不下，表格被赶到图纸另一头。另加 `1e-6*cell` 偏置抵消 `119.9999…` 这类浮点误差。
- **方向**：`prefer` 取 `top-left / top-right / bottom-left / bottom-right`（"top" 指模型坐标 y 大的一侧）。
- **留缝**：`margin` 同时用于内框内缩和占用框外扩，保证与图框、图元都有缝。

### 47.3 落位区优先级

| 顺序 | 区域 | 说明 |
|---|---|---|
| 1 | 图签上方横带 | `y` 从图签顶标高到"图形在图签之上的最低边"，`x` 为内框全宽。最常规的附表摆法 |
| 2 | 图形右侧竖带 | 横带放不下时退到右侧 |
| 3 | 整个内框 | 兜底 |

横带上界用"图形在图签之上的最低边"而不是"全部图元的最高边"，是因为施工说明落在图签顶**以下**，用整体外包会把横带挤成 0 高。

### 47.4 大表先落位、小表跟随

两张附表按面积**从大到小**排；第一张定下落位区后，第二张只允许在该区及更差的区里找（`floor_band`）。

原因很具体：一层房间面积表 20 行（88.6mm 高）勉强能进 95mm 的横带，二层 31 行（124.6mm）进不去。若各自独立找位，二层的门窗表留在横带、面积表飞到右上角，两张表分家，一套图里各层排法还不一致。跟着走之后：一层两张都在图签上方，二至五层两张都在右上，**同一张图内永不拆开**。

留缝不够时按 `1.0 → 0.5 → 0.25` 逐级收紧（6mm → 3mm → 1.5mm），且**先按落位区优先级走、同区内再收紧**——反过来会变成"次优区+宽松留缝"抢在"最优区+紧凑留缝"前面得手。

### 47.5 表格用哪张

- 门窗表走 `create_opening_table`（规范 7 列：序号/编号/类别/洞口尺寸/窗台高/樘数/所在层），**不用** `openings_report` 那张 6 列旧表——它的"所在墙"列填的是 `W001;W003` 这类内部墙号，施工方看不懂，长串还会把格子挤爆。
- 房间面积表走 `rooms_report` 的 4 列（编号/名称/净面积 m²/周长 mm）。
- 指北针走 `create_north_arrow`（直径 24mm，`AA_SYM_N<k>`）。

### 47.6 可重复执行

`place --replace` 先调 `clear_schedules()`：只删 `AA_TITLE ∈ {门窗表, 房间面积表}` 的表和 `AA_KIND=NORTH` 的符号，**不碰**图纸目录、楼层表等其它表。不这么做的话，调一次位置就多一张表。

### 47.7 顺带修掉的三处判定缺陷

指标算错比指标缺失更坏，因为它让人以为图没问题：

| 缺陷 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 属性定义被当成可见图元 | 一层平面图 `ATTDEF` 1201 个、真实图元 646 个，`occupancy` 虚高（0.336 → 0.315） | `_quality_pieces` 把块内全部实体都算进去，`ATTDEF` 坐标留在块定义原点，跟着 `INSERT` 变换后凭空造框 | 排除 `ATTDEF / ATTRIB / SEQEND` |
| 文字外包退化成零面积点 | "主题：…"落进图签框也报不出来 | `_piece_box` 按"插入点 ± 半径"算，宽度信息全丢；`title_block_overlap` 索性把 `TEXT` 整类排除 | 文字按 插入点(左下) + 估算字宽 + 字高 成框，压线检查纳入 `TEXT/MTEXT` |
| 表格文字顶出格子 | 一串墙号把字顶到邻列甚至表格外 | `draw_table` 自绘版不看列宽，与它自称要解决的问题同构 | 单元格文字先缩字（最紧 70%），还超就截断加省略号；返回值报 `shrunk/truncated`。**表格尺寸不变，字不出格** |

另外：图纸说明标题原来写死在"第 6 行上方"，说明一加行就压到第一行字上；本层标高/主题按 `ay+4200` 摆，正好落进图签框（-18700~-13100）。两处都改成按行数算 / 挪到说明区右端同一行。

### 47.8 验收

## §48 门窗 / 楼梯平面图例（v1.0.59）

这一版没有新构件，只把 `AA_OPENING_<id>` 与 `AA_STAIR_<id>` 的**块内几何**改成合规图例。属性只增不改，老图仍可读。

### 48.1 门窗：本地坐标与四个图例参数

块参照仍插在"墙起点 + 墙旋转角"，因此块内 `+X` 沿墙、`+Y` 为墙法向，洞口必然贴墙。洞口两端各一条竖线（`x1/x2`，从 `-thick/2` 到 `+thick/2`）是所有类型共用的，之后按 `AA_KIND` 分支：

| 类型 | 块内几何 |
|---|---|
| `WINDOW` | 四条平行线：`±thick/2`（贴墙面，墙块在洞口处已断开，这里补回轮廓）+ `±(thick/2 − frame)`（窗框内沿） |
| `DOOR` | 单扇：铰点端一条垂直墙面、长 = 洞口宽的**门扇线** + 90° **开启弧**；双扇：两扇各半宽，铰点分别落在两端，两弧在中点相接 |
| `DOORWIN` | `doorpart` 宽的门扇（同上，带弧）在铰点端 + 其余部分走窗四线 + 分界处一条**中梃**竖线 |

新增属性：

| 属性 | 含义 |
|---|---|
| `AA_HINGE` | `±1`，铰点落在洞口左端（+1）/ 右端（−1） |
| `AA_SWING` | `±1` 为显式开向（本地 +Y / −Y）；**`0` 表示自动**，由室内外判定，房间尚未建立时退回 +Y |
| `AA_LEAVES` | 平开门扇数，`0` 提交时按洞口宽自动（≥1200 双扇），落地后回读为 1 或 2；窗与门连窗固定 1 |
| `AA_DOORPART` | 门连窗里门扇占的宽度，0 表示取洞口一半；落地时夹在洞口宽的 20%~80% |

弧角由"铰点端 × 开向"四种组合唯一确定（DXF 组 50/51 回读为**度**）：

| 组合 | 弧 |
|---|---|
| 铰点在左、向 +Y | 0° → 90° |
| 铰点在左、向 −Y | 270° → 360° |
| 铰点在右、向 +Y | 90° → 180° |
| 铰点在右、向 −Y | 180° → 270° |

`split / merge / reconcile / copy-floor / rescale` 五处内部重建都会把上面四项原样透传——顺带修掉了这些路径**不传 `frame/no/label_side`、把自定义门窗编号按尺寸重算掉**的旧缺陷。

### 48.2 楼梯：进深、剖断线与裁剪规则

本地原点为楼梯间起步边中点，`+Y` 上行，`总进深 = 梯段长 + 平台深`（两跑并排、平台在尽端），`x` 方向总宽 `2×梯段宽 + 梯井宽`。

剖断线取 45°，因此需要 `梯段宽` 那么大的竖向空间：

```
cutL = clamp(0.30 × 梯段长, 1×踏步宽, 梯段长 − 踏步宽)
cutR = min(cutL + 梯段宽, 梯段长)          左低右高
剖断线：(x左 − 0.4 踏, cutL − 0.4 踏) → (x右 + 0.4 踏, cutR + 0.4 踏)
```

先层/中层都用这一条线，差别只在**踏步是否裁剪**：

| 层 | 画法 |
|---|---|
| `FIRST` | 只画上行第一跑。左边线到 `cutL`、右边线到 `cutR`；踏步 `y ≤ cutL` 画全长，`cutL < y ≤ cutR` 从斜线交点画到右边线，`y > cutR` 不画；箭头杆止在梯段中心处的斜线高度 |
| `MIDDLE` | 两跑全画踏步，剖断线压在第一跑上表示剖切位置，加"绕一圈"箭头（上行 → 平台横折 → 下行）与"上/下" |
| `TOP` | 两跑全画，只沿第二跑画一条从平台指向楼面的"下"箭头，**没有剖断线** |

梯井多段线只贯通梯段（`y` 从 0 到梯段长），不穿平台——平台是整块板，井到平台内边就结束。"上/下"写在起步那一格踏步内（`0.10 踏步宽` 高、梯段中心右侧 `0.7 字高`），由 `aa:stair-label` 把**可见左下角**对齐到目标点（块旋转 180° 时插入点要先右移、上移一个字高）。
