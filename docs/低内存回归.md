# 低内存回归（Windows 16 GB）

## 为什么全量测试会把桌面拖黑

`cadcraft-cli` 的失败信息是 `memory allocation of 23296 bytes failed`，不是申请 8 GB 失败。
当时物理内存还有约 5.9 GB，但 `FreeVirtualMemory` 只剩几十 MB：Windows 的**可提交额度**耗尽，
`dwm/explorer` 也被饿死，所以黑屏只剩鼠标。

## 两条硬规则

1. 每个用例前检查 `ullAvailPageFile`（可提交额度），低于 `--min-avail-mb` 直接停，不再硬跑。
2. 测试进程树放进 Windows Job Object，`--job-mb` 超限只杀测试树，不碰桌面。

## 跑法

```powershell
# 只列测试
.\tools\RunTestsSafe.ps1 -List

# 默认：至少 2 GB 可提交、每个测试树硬上限 2 GB、用例间冷却 5 秒
.\tools\RunTestsSafe.ps1

# 更保守
.\tools\RunTestsSafe.ps1 -MinAvailMB 3072 -JobMB 1536 -Cooldown 10
```

## 页面文件

先只检查：

```powershell
.\tools\CheckPagefile.ps1
```

如果页面文件很小（例如 16 GB 机器只有 2 GB 页面文件），提交上限会非常紧。
在 C: 有足够空间时，用管理员 PowerShell：

```powershell
.\tools\CheckPagefile.ps1 -Apply -InitialMB 16384 -MaximumMB 32768
```

改完必须重启。不要再把 `FreePhysicalMemory` 当安全信号，它和提交额度不是一回事。

## 本机基线（2026-11-25）

```text
页面文件 C:\pagefile.sys：当前 20000 MB / 峰值 793 MB
提交额度：35.2 GB，可用 22.5 GB
C: 空闲：84.7 GB
```

这组数值下页面文件够用，不需要 `-Apply`。全量 `RunTestsSafe.ps1` 跑完 62/62，0 FAIL。

## 脚本编码

`CheckPagefile.ps1`、`RunTestsSafe.ps1` 必须保存为 **UTF-8 with BOM**。Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读取，中文字符串直接变成乱码并触发语法解析错误。
